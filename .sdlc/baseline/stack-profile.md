# Stack profile — learned from repo scan

Built 2026-10-29 for run 20261029-212654-refactor-react18-only. The scan was sampled and focused on frontend render paths and package manifests, because the run intent is the react18-only refactor.

## Language & runtime

TypeScript `~5.7.0` across the monorepo. Node `22 || 24`. Yarn 4.18.1 with `nodeLinker: node-modules`. Package sources are ESM-style TS, which `backstage-cli` compiles. Some CLI config files are CJS JS (for example `packages/cli-module-test-jest/config/jest.js` uses `require.resolve`). Tests run on Jest 30 through `backstage-cli package test` with `--experimental-vm-modules`.

## Framework

Backstage's own plugin framework, with two frontend systems and one backend system:

- Old frontend: `core-*` packages (`@backstage/core-plugin-api`, `core-components`, `core-app-api`).
- New frontend: `frontend-*` packages (`createFrontendPlugin` from `@backstage/frontend-plugin-api`).
- Backend: `backend-*` packages (`createBackendPlugin`, `coreServices`), with Express routers underneath.

UI is React 18 (the apps), Material UI v4, `@backstage/ui`, and react-router-dom v6.

## Conventions detected

### File naming

- PascalCase component folders, with the component, test and index together: `plugins/catalog/src/components/SystemDiagramCard/SystemDiagramCard.tsx` and `SystemDiagramCard.test.tsx`.
- camelCase for non-component modules: `renderReactElement.ts`, `hasReactDomClient.ts`, `appPlugin.ts`.
- Each package has a `report.api.md` (or `report-alpha.api.md`) API-Extractor report, regenerated by `yarn build:api-reports` and never hand-edited.

### React render / React 17 compatibility shim (the target of this refactor)

`plugins/techdocs/src/reader/transformers/renderReactElement.ts`:

```ts
let ReactDOMPromise: Promise<
  typeof import('react-dom') | typeof import('react-dom/client')
>;
if (process.env.HAS_REACT_DOM_CLIENT) {
  ReactDOMPromise = import('react-dom/client');
} else {
  ReactDOMPromise = import('react-dom');
}

/** @internal */
export function renderReactElement(element: JSX.Element, root: HTMLElement) {
  ReactDOMPromise.then(ReactDOM => {
    if ('createRoot' in ReactDOM) {
      ReactDOM.createRoot(root).render(element);
    } else {
      ReactDOM.render(element, root);
    }
  });
}
```

The same pattern is in `packages/dev-utils/src/devApp/render.tsx`. The flag is injected at build time by `packages/cli-module-build/src/lib/bundler/config.ts`, which defines `'process.env.HAS_REACT_DOM_CLIENT': JSON.stringify(hasReactDomClient())` using `hasReactDomClient.ts` (`require.resolve('react-dom/client', ...)`). Under Jest it is set by `packages/cli-module-test-jest/config/jest.js`, which sets `process.env.HAS_REACT_DOM_CLIENT = true` when `react-dom/client` resolves.

The React-18-only shape is already in use at `packages/app/src/index.tsx`:

```tsx
import ReactDOM from 'react-dom/client';
ReactDOM.createRoot(document.getElementById('root')!).render(app);
```

Tests use `describe/it`, `renderInTestApp` from `@backstage/test-utils` (or `frontend-test-utils` for the new system), RTL `screen`, and MSW for HTTP (ADR007). AGENTS.md prefers fewer, thorough tests and `findBy*` over `waitFor`, with no test IDs.

### Config

App config is in `app-config*.yaml`, read via `coreServices.rootConfig` (backend) or `configApiRef` (frontend). Each package can declare its schema in a `config.d.ts`. Env vars are used mainly by tooling (`BACKSTAGE_*`, `HAS_REACT_DOM_CLIENT`, `NODE_ENV`).

### Data layer

Backend plugins use Knex through `coreServices.database`, with migrations per plugin. OpenAPI clients and servers are generated into `src/schema/openapi/generated/`. Do not hand-edit them.

### Framework-owned wiring

- Backend: `packages/backend/src/index.ts` calls `backend.add(import('@backstage/plugin-...'))`.
- New frontend: features are discovered from `packages/app` dependencies, and extensions are declared in the plugin's `alpha` entry.
- Old frontend: explicit `createApp` and routes in `packages/app-legacy/src/App.tsx`.

## Notes for downstream codegen

- Match each package's local style: AGENTS.md puts consistency within a package above consistency across the repo.
- New files need the Apache-2.0 header with year 2026. Never change the year on existing headers.
- Narrowing `react` peer ranges is an adopter-facing change to published packages:
  - It needs changeset coverage in `.changeset/*.md`. Edit those files by hand, check the 42 existing changesets first, and follow the bump rules (breaking below 1.0 is `minor`, at 1.0 or above is `major`).
  - Messages must not name internal symbols such as `HAS_REACT_DOM_CLIENT`.
- Changing an exported signature requires regenerating `report*.api.md` with `yarn build:api-reports`. Do not hand-edit the reports.
- Do not edit ESLint, Prettier or TS configs, `docs/releases/**`, or generated OpenAPI folders.
- Validate with `CI=1 yarn test <path>` and `yarn tsc` from the repo root.
