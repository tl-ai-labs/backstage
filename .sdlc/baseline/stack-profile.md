# Stack profile: learned from repo scan (Backstage monorepo, scaffolder focus)

## Language & runtime

TypeScript ~5.7 (strict) on Node 22 or 24. Yarn 4 workspaces (`packages/*`, `plugins/*`). Packages are ESM-style TS sources: `main: src/index.ts`, and `exports` maps `.`, `./alpha` and `./testUtils` straight to the `.ts` sources. Packages are built by `backstage-cli` (never run `yarn build`). Type-check runs only from the root: `yarn tsc`.

## Framework

Backstage frontend plugins: React 18, `@backstage/core-plugin-api` (`useApi`, `useApiHolder`, `useAnalytics`, `featureFlagsApiRef`), `@backstage/frontend-plugin-api` (`useTranslationRef`), MUI v4 (`@material-ui/core`) alongside `@backstage/ui` (BUI `Button`, `onPress`/`isDisabled`). Forms use react-jsonschema-form 5.24.13 (`@rjsf/core` `withTheme`, `@rjsf/validator-ajv8` `customizeValidator` + `ajv-errors`). Schemas are resolved with `json-schema-library` (`Draft07`).

## Conventions detected

### File naming

- Components use PascalCase folders with a barrel: `next/components/Stepper/Stepper.tsx` and `index.ts`, with the test beside the file as `Stepper.test.tsx`.
- Hooks use one camelCase file per hook: `next/hooks/useTemplateSchema.ts`, re-exported through `next/hooks/index.ts` with named exports (ADR003: no default exports).
- Plain helpers live in `next/lib/schema.ts` (exported through `next/lib/index.ts`).

### Header & doc tags

Every source file starts with the Apache 2.0 header (`Copyright 2022 The Backstage Authors` on existing files; new files use 2026). Exported symbols carry TSDoc release tags (`@alpha` for `next/` code, `@public` in scaffolder-common), and API reports (`report*.api.md`) are regenerated by `yarn build:api-reports`.

### Hook shape

```ts
export const useTemplateSchema = (
  manifest: TemplateParameterSchema,
): {
  steps: ParsedTemplateSchema[];
  presentation?: TemplatePresentationV1beta3;
} => {
  const featureFlags = useApi(featureFlagsApiRef);
  const steps = manifest.steps.map(({ title, description, schema }) => ({
    title,
    description,
    mergedSchema: schema,
    ...extractSchemaFromStep(schema),
  }));
```

(from `plugins/scaffolder-react/src/next/hooks/useTemplateSchema.ts`). Hooks are arrow-function `const` exports with explicit return types, and they use `useMemo` where results get passed down (`useFilteredSchemaProperties`).

### Pure helper shape

```ts
export const extractSchemaFromStep = (
  inputStep: JsonObject,
): { uiSchema: UiSchema; schema: JsonObject } => {
  const uiSchema: UiSchema = {};
  const returnSchema: JsonObject = parse(stringify(inputStep));
  extractUiSchema(returnSchema, uiSchema);
  return { uiSchema, schema: returnSchema };
};
```

(from `next/lib/schema.ts`). Inner helpers are plain `function`s with an `isObject` guard. Types come from `@backstage/types` (`JsonObject`, `JsonValue`).

### Test shape

```tsx
describe('Stepper', () => {
  it('should remember the state of the form when cycling through the pages', async () => {
    const manifest: TemplateParameterSchema = { steps: [ ... ], title: '...' };
    const { getByRole } = await renderInTestApp(
      <SecretsContextProvider>
        <Stepper manifest={manifest} extensions={[]} onCreate={jest.fn()} />
      </SecretsContextProvider>,
    );
    await act(async () => {
      fireEvent.change(getByRole('textbox', { name: 'name' }), { target: { value: 'im a test value' } });
      fireEvent.click(getByRole('button', { name: 'Next' }));
    });
```

Jest via `backstage-cli`. Tests use `describe`/`it('should ...')`, and `renderInTestApp` from `@backstage/test-utils`. Hook tests use `renderHook` + `TestApiProvider` + `mockApis` from `@backstage/frontend-test-utils` (`useTemplateSchema.test.tsx`). Project guidance for new tests: fewer, thorough tests; prefer `screen` + `findBy*` over `waitFor`; no test IDs.

### Config

Not relevant to this package. Template behavior comes from the template YAML (`spec.parameters`). Backstage uses its keys prefixed `ui:` (moved into the rjsf uiSchema), `ui:backstage` (`featureFlag`, `review`) and `backstage:` (`backstage:featureFlag`, `backstage:permissions`).

### Data layer

None in the frontend. The schema comes from `scaffolderApi.getTemplateParameterSchema` (`useTemplateParameterSchema`). The backend (`plugins/scaffolder-backend/src/service/router.ts`) validates submitted values against each parameter step with `jsonschema.validate`.

### Framework-owned wiring

`Workflow` (scaffolder-react `next/components/Workflow/Workflow.tsx`) does `useTemplateParameterSchema`, then `useFilteredSchemaProperties`, then `<Stepper manifest=... extensions=... layouts=... />`. The scaffolder plugin pages (`plugins/scaffolder/src/alpha/components/TemplateWizardPage/TemplateWizardPage.tsx`, and the template editor's `TemplateFormPreviewer.tsx`) host it.

## Notes for downstream codegen

- New `next/` exports need `@alpha` TSDoc, a re-export through the right `index.ts` barrel, a changeset (scaffolder-react is 3.0.0-next.0, so a new feature is `minor`), and regenerated API reports. Do not hand-edit `report*.api.md`.
- New template keys should follow the existing namespaces: `ui:backstage.<option>` inside the uiSchema, or the `backstage:` prefix on schema nodes. Any `ui:*` key is moved out of the schema automatically by `extractSchemaFromStep`.
- Do not mutate the manifest. Follow `useFilteredSchemaProperties` (cloneDeep, then prune `required` for removed keys).
- Keep formatting Prettier-compatible (2 spaces, single quotes, trailing commas). Run `yarn prettier --write` only on changed files.
