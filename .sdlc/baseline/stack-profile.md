# Stack profile: learned from repo scan

Built 2026-11-04 for run 20261104-130720-feature-new-entity-rename-redirect. Trigger: the dominant stack
(TypeScript + Backstage framework, React frontend, Express/knex backend) has no shipped adapter (only
generic, nest, python exist). Sampling was focused on the catalog and TechDocs packages.

## Language & runtime
TypeScript ~5.7 across a Yarn 4 workspaces monorepo (`packages/*`, `plugins/*`; nodeLinker node-modules),
Node 22 or 24. Packages are built and tested through `backstage-cli` (`backstage-cli package test` = Jest 30).
Source is ESM-style `import`; knex migrations are plain CommonJS `.js` with `// @ts-check` and JSDoc types.
Every new `.ts/.tsx/.js/.jsx` source file starts with the Apache 2.0 header using the current year
(`Copyright 2026 The Backstage Authors`); existing headers keep their original year.

## Framework
Backstage (in-repo framework). Three generations live side by side:
- Backend system: `@backstage/backend-plugin-api` (`createBackendPlugin`, `env.registerInit({ deps, init })`, `httpRouter.use(router)`).
- New frontend system: `@backstage/frontend-plugin-api` (`PageBlueprint`, `createExtensionBlueprint`, extension inputs/data refs), wired in each plugin's `src/alpha/`.
- Old frontend system: `@backstage/core-plugin-api` (`createRouteRef`, `useApi`, `useRouteRefParams`), still used by components the alpha wiring reuses.
UI is Material UI v4 (`@material-ui/core`) in these plugins, plus `@backstage/ui` elsewhere. Translations go through `useTranslationRef(<plugin>TranslationRef)`.

## Conventions detected

### File naming
- React components: PascalCase folder + file, with `index.ts` barrel: `plugins/catalog/src/components/EntityNotFound/EntityNotFound.tsx`, `.../EntityNotFound.test.tsx`, `.../index.ts`.
- Hooks: camelCase `useX.ts(x)`: `plugins/catalog/src/components/CatalogEntityPage/useEntityFromUrl.ts`, `plugins/catalog-react/src/hooks/useEntity.tsx`.
- Backend classes: PascalCase one class per file: `plugins/catalog-backend/src/service/DefaultEntitiesCatalog.ts`, `AuthorizedEntitiesCatalog.ts` (decorator class wrapping the default with permission checks).
- Backend functions: camelCase `createRouter.ts`; request parsers `request/parseEntityQuery.ts`.
- Tests sit next to the file: `X.test.ts` / `X.test.tsx`.
- Migrations: `migrations/YYYYMMDDHHMMSS_snake_description.js` (latest `20261007000000_stitch_failure_count.js`).

### Handler / controller shape
Express router in `plugins/catalog-backend/src/service/createRouter.ts` (956 lines), built on an OpenAPI-typed
router (`createOpenApiRouter` from `../schema/openapi`; spec in `src/schema/openapi.yaml`, generated code in
`src/schema/openapi/generated/`). Every handler opens an auditor event and resolves credentials:
```ts
router
  .get('/entities', async (req, res) => {
    const auditorEvent = await auditor.createEvent({
      eventId: 'entity-fetch',
      request: req,
      meta: { queryType: 'all', query: req.query },
    });
    try {
      const filter = parseEntityFilterParams(req.query);
      const credentials = await httpAuth.credentials(req);
      ...
      await auditorEvent?.success();
    } catch (err) {
      await auditorEvent?.fail({ error: err });
      throw err;
    }
  })
```
Entity lookup by name is `GET /entities/by-name/:kind/:namespace/:name` (line ~423, `queryType: 'by-name'`).
Errors come from `@backstage/errors` (`NotFoundError`, `InputError`). A new route needs the OpenAPI spec
updated and the generated router and client regenerated by repo tooling, not hand-edited.

### Service shape
`export class DefaultEntitiesCatalog implements EntitiesCatalog` with `async` methods (`entities`,
`entitiesBatch`, `queryEntities`, `removeEntityByUid`, `entityAncestry`, `facets`); the interface lives in
`src/catalog/types.ts`. `AuthorizedEntitiesCatalog` wraps it to apply permissions. The plugin wires
services in `src/service/CatalogPlugin.ts` (`createBackendPlugin({ pluginId: 'catalog', register(env) { env.registerInit({ deps: {...}, async init(...) {...} }) } })`).

### Test shape
Backend (`createRouter.test.ts`): Jest + supertest + `@backstage/backend-test-utils` (`mockServices`,
`mockCredentials`, `TestDatabases`), `jest.Mocked<Interface>` objects with `jest.fn()` members,
`wrapServer` from `@backstage/backend-openapi-utils/testUtils`, `jest.setTimeout(60_000)` for DB-backed tests.
Frontend (`EntityNotFound.test.tsx`):
```tsx
import { renderInTestApp } from '@backstage/test-utils';
import { screen } from '@testing-library/react';

describe('<EntityNotFound />', () => {
  it('renders without exploding', async () => {
    await renderInTestApp(<EntityNotFound />);
```

The repo asks for fewer, more thorough tests; `screen` and `findBy*` rather than `waitFor`; no test IDs.
`.cursor/rules/tests/*.mdc` document the test-utils idioms (read-only reference).

### Config
Static config schema in each package's `config.d.ts` (`export interface Config { catalog?: { ... } }`, with
TSDoc comments, `@visibility` tags where frontend-visible). Read at runtime with `@backstage/config`
`Config` (`config.getOptionalBoolean(...)`, etc.). Zod (`zod/v3` on the backend router, `zod/v4` in the new
frontend config schemas) validates request bodies and extension config.

### Data layer
knex (Postgres, SQLite and MySQL in tests through `TestDatabases`). Row types in
`plugins/catalog-backend/src/database/tables.ts` (`DbRefreshStateRow`, `DbLocationsRow`, ... with TSDoc per
column). Migrations run via `applyDatabaseMigrations` (`knex.migrate.latest({ directory: resolvePackagePath('@backstage/plugin-catalog-backend', 'migrations') })`).
```js
// @ts-check

/** @param {import('knex').Knex} knex */
exports.up = async function up(knex) {
  await knex.schema.alterTable('stitch_queue', table => {
    table.integer('failure_count').notNullable().defaultTo(0);
  });
};

/** @param {import('knex').Knex} knex */
exports.down = async function down(knex) {
  await knex.schema.alterTable('stitch_queue', table => {
    table.dropColumn('failure_count');
  });
};
```
Entity refs are stored lowercase `kind:namespace/name` (`entity_ref`); `entity_id` is regenerated each time a
refresh_state row is added. Final data lives in `final_entities` after stitching (`src/stitching/DefaultStitcher.ts`).

### Framework-owned wiring
- Backend: `httpRouter.use(router)` inside the catalog plugin's `registerInit` (`CatalogPlugin.ts` ~line 285).
- Frontend (old system): the entity page loads through `CatalogEntityPage` -> `AsyncEntityProvider {...useEntityFromUrl()}`;
  `useEntityFromUrl` reads `{ kind, namespace, name }` from `useRouteRefParams(entityRouteRef)` and calls
  `catalogApi.getEntityByRef(...)` with `useAsyncRetry`. `entityRouteRef` is a global singleton in
  `plugins/catalog-react/src/routes.ts`.
- Frontend (new system): `plugins/catalog/src/alpha/pages.tsx` builds pages with `PageBlueprint` and
  `createExtensionBlueprint`, reusing `entityRouteRef` via `convertLegacyRouteRef`.
- TechDocs already has a redirect notice: `plugins/techdocs/src/reader/components/TechDocsRedirectNotification/TechDocsRedirectNotification.tsx`
  (MUI `Snackbar` + "redirect now" button, text from `techdocsTranslationRef`), used by
  `reader/transformers/handleMetaRedirects.tsx`.

## Notes for downstream codegen
- Match each package's own style; consistency within a package outranks consistency across the repo.
- New source files need the Apache 2.0 header with year 2026; do not touch years on existing files.
- No default exports (ADR003); no `React.FC` (ADR006); use `fetch` via the fetch API (ADR014); use MSW for request mocking (ADR007).
- Any public API change in a non-private package needs a changeset in `.changeset/` (written by hand, never via the CLI) and regenerated `report*.api.md` (via `yarn build:api-reports`, not by hand). `@backstage/catalog-model` is at 1.10.2 (new API = minor); the plugins here are on `-next` pre-release versions.
- Do not hand-edit `src/schema/openapi/generated/**` in catalog-backend or catalog-client; change `openapi.yaml` and regenerate with repo tooling.
- New DB columns or tables mean a new migration file with a later timestamp than 20261007000000, plus a matching `down`.
- Features must ship documentation (TSDoc, package README, or `/docs/features/...`) following `docs/contribute/doc-style-guide.md`.
- Frontend changes usually need both the old-system component path and the `src/alpha` new-system wiring considered.
