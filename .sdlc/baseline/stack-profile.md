# Stack profile: learned from repo scan

Built 2026-10-29 for run `20261029-feature-new-entity-former-names`. Trigger: no pre-authored adapter matches (Backstage TypeScript monorepo).

## Language & runtime

TypeScript ~5.7 on Node 22 || 24, with Yarn 4.18.1 workspaces (`packages/*`, `plugins/*`). Source is ESM-style TS compiled by `@backstage/cli`. Knex migrations are plain CommonJS JS with `// @ts-check`. Prettier config is `@backstage/cli/config/prettier` (single quotes, trailing commas, 2-space indent). Every new `.ts/.tsx/.js` source file needs the Apache 2.0 header with the **current year** (2026). Existing headers keep their year.

## Framework

Backstage. The backend uses `createBackendPlugin` + `coreServices` DI, with Express routers built in `createRouter.ts` and Knex for the DB. The frontend has two systems side by side: the old one (`@backstage/core-plugin-api`, `src/components/**`) and the new one (`@backstage/frontend-plugin-api`, `src/alpha/**`). UI uses MUI v4 (older components) and `@backstage/ui` (BUI, newer components).

## Conventions detected

### File naming

- One component per PascalCase folder with an `index.ts` barrel: `plugins/catalog/src/components/EntityOrphanWarning/{EntityOrphanWarning.tsx,EntityOrphanWarning.test.tsx,index.ts}`.
- Classes are PascalCase files (`DefaultEntitiesCatalog.ts`, `DefaultNamespaceEntityPolicy.ts`). Hooks are camelCase (`useEntityFromUrl.ts`, `useExternalRedirect.ts`).
- Tests sit next to the file as `*.test.ts(x)`.
- Migrations are `plugins/catalog-backend/migrations/YYYYMMDDHHMMSS_snake_name.js`.

### Exports / API docs

Public exports carry TSDoc with a release tag (`@public` / `@alpha`) and flow through `src/index.ts` (and `src/alpha.ts`). API reports (`report*.api.md`) are generated by `yarn build:api-reports` and are never hand-edited.

### Handler / route shape (catalog-backend `src/service/createRouter.ts`)

```ts
.get('/entities/by-name/:kind/:namespace/:name', async (req, res) => {
  const { kind, namespace, name } = req.params;
  const entityRef = stringifyEntityRef({ kind, namespace, name });
  const auditorEvent = await auditor.createEvent({
    eventId: 'entity-fetch', request: req,
    meta: { queryType: 'by-name', entityRef: entityRef },
  });
  try {
    const { items } = await entitiesCatalog.entitiesBatch({
      entityRefs: [stringifyEntityRef({ kind, namespace, name })],
      credentials: await httpAuth.credentials(req),
    });
    await auditorEvent?.success();
    writeSingleEntityResponse(res, items, `No entity named '${name}' found, ...`);
  } catch (err) {
    await auditorEvent?.fail({ error: err });
    throw err;
  }
})
```

### Frontend component shape (old frontend system, catalog)

```tsx
export function isOrphan(entity: Entity): boolean {
  return entity?.metadata?.annotations?.['backstage.io/orphan'] === 'true';
}

/** Displays a warning alert ... @public */

  const { entity } = useEntity();
  const { t } = useTranslationRef(catalogTranslationRef);

```

User-facing strings go through translation refs (`plugins/catalog/src/alpha/translation.ts`, `plugins/techdocs/src/translation.ts`), not literals. TechDocs already has a MUI `Snackbar` redirect notice (`TechDocsRedirectNotification`, keys `redirectNotification.*`).

### Data loading in pages

`useAsyncRetry(() => catalogApi.getEntityByRef({ kind, namespace, name }), [...])` in `useEntityFromUrl.ts`. Navigation uses `react-router-dom` `useNavigate`, and route targets come from `useRouteRef(entityRouteRef)`.

### Test shape

- Frontend: Jest + RTL with `renderInTestApp` and `TestApiProvider` from `@backstage/test-utils` (or `frontend-test-utils` for alpha), wrapped in `EntityProvider`, using `mountedRoutes` for route refs, and `screen.findBy*` queries. Prefer fewer, thorough tests.

```tsx
await renderInTestApp(
  <TestApiProvider apis={[[catalogApiRef, { removeEntityByUid: jest.fn() }]]}>
    <EntityProvider entity={entity}>
      <EntityOrphanWarning />
    </EntityProvider>
  </TestApiProvider>,
  { mountedRoutes: { '/create': rootRouteRef } },
);
```

- Backend DB: `TestDatabases.create()` + `describe.each(databases.eachSupportedId())` + `applyDatabaseMigrations(knex)`, `mockServices.logger.mock()`, `jest.setTimeout(60_000)`.
- Router tests use supertest against `createRouter` with mocked services (`createRouter.test.ts`).

### Config

`coreServices.rootConfig` (`@backstage/config`), with app-config YAML. Packages declare their config schema in `config.d.ts`. No env-validator libraries.

### Data layer

Knex. Tables are typed in `plugins/catalog-backend/src/database/tables.ts`. Migrations look like this:

```js
// @ts-check
/** @param {import('knex').Knex} knex */
exports.up = async function up(knex) {
  await knex.schema.alterTable('stitch_queue', table => {
    table.integer('failure_count').notNullable().defaultTo(0);
  });
};
```

Any query, index or schema change in catalog-backend must be checked with the query battery (`src/tests/performance/query-battery/`, per `plugins/catalog-backend/CLAUDE.md`).

### Framework-owned wiring

Backend: `createBackendPlugin({ pluginId: 'catalog', register(env) { env.registerInit({ deps: { logger: coreServices.logger, database: coreServices.database, httpRouter: coreServices.httpRouter, ... }, async init(...) {...} }) } })` in `plugins/catalog-backend/src/service/CatalogPlugin.ts`. Old frontend: route refs in `src/routes.ts` + `plugin.ts`. New frontend: extensions in `src/alpha/*.tsx` (`pages.tsx`, `entityContents.tsx`).

### Changesets

`.changeset/<slug>.md` with YAML front matter `'@backstage/plugin-x': patch|minor` and an adopter-facing description with no internal symbols. Write the files directly and never use the changeset CLI. Packages below 1.0.0 take `patch` for new features. At 1.0.0 and above, new APIs take `minor`.

## Notes for downstream codegen

- Match each package's own style. Consistency inside a package beats consistency across the repo.
- Change both frontend systems when a page behavior changes: `src/components/**` (old) and `src/alpha/**` (new).
- Put new strings in the package translation ref. Add TSDoc + a release tag on every new public export, then regenerate API reports with the tool.
- Use `stringifyEntityRef` / `parseEntityRef` from `@backstage/catalog-model` for ref handling, and never concatenate refs by hand.
- Do not edit CHANGELOG.md, `report*.api.md`, `docs/releases/**`, or ESLint/Prettier/TS config.
