## Decisions

- Shape of the shared finalization signal (FR-1): Two optional members on the public `RouteResolutionApi` interface in frontend-plugin-api: `isFinalized?(): boolean` (false while the app is still in bootstrap) and `onFinalized?(listener: () => void): () => void` (calls the listener once when the app is finalized; returns an unsubscribe function). (not a separate lifecycle Utility API ref (core-compat-api and adopters would need a second implementation, and core-plugin-api would need another lookup); not module-level state in @internal/frontend (each package inlines its own copy, and core-plugin-api does not import it); not an `isBootstrapping` flag (absent members must read as finalized, which `isFinalized` expresses without negation)) — Both hooks already hold the same `RouteResolutionApiProxy` object via `useApi(routeResolutionApiRef)`; optional members keep `CompatRouteResolutionApi` and adopter implementations compiling unchanged (NFR-1).
- How an implementation without the members is read: An API object is treated as finalized unless both `isFinalized` and `onFinalized` are functions and `isFinalized()` returns false; a missing API object (legacy app) is also finalized. Finalized-at-mount means no subscription and no extra render. (not treating a lone `isFinalized` without `onFinalized` as bootstrap (it could never leave bootstrap)) — FR-1 and FR-6: implementations lacking the members behave exactly as today.
- Where bootstrap ends: `RouteResolutionApiProxy` gets a new `markFinalized(): void` method. `initialize()` is unchanged and never finalizes, so the startup call from treeLifecycle.tsx keeps the API in bootstrap. prepareSpecializedApp.tsx calls `options.phase.routeResolutionApi.markFinalized()` directly after each of its two `instantiateAndInitializePhaseTree(...)` calls (the normal finalization at line 689 and the bootstrap-error finalization at line 758), before the root element check. (not a `finalize` flag on `initialize()` or on `instantiateAndInitializePhaseTree` (spreads the lifecycle into the shared helper that the startup path also uses); not marking after the root element check (the 689 path would not fire when its element check throws, contradicting AC-7's 689-then-758 case)) — Keeps treeLifecycle.tsx (outside the allowlist) untouched and makes the two finalization sites explicit.
- Firing semantics: `markFinalized()` is a no-op once `#finalized` is true. Otherwise it sets `#finalized = true`, copies the listener set into an array, clears the set, then calls each listener synchronously in registration order. `onFinalized()` called when already finalized registers nothing and returns a no-op unsubscribe; the hooks re-check `isFinalized()` after subscribing. — The signal fires at most once for the life of the API object even when both finalization paths run (FR-1, AC-7), and listeners are released.
- Hook subscription pattern (FR-2, FR-4, FR-5): Each hook file gets its own private (non-exported) `useRouteResolutionFinalized(api)` hook: `const [signalled, setSignalled] = useState(false)`; `finalized = signalled || isRouteResolutionFinalized(api)` computed every render; a `useEffect` on `[api, finalized]` that returns `undefined` when `finalized` is true or the API lacks the members, otherwise subscribes with `api.onFinalized(() => setSignalled(true))`, then re-checks `api.isFinalized()` and calls `setSignalled(true)` if it is already true, and returns the unsubscribe. The returned boolean is added to the resolution `useMemo` deps so it re-runs exactly once at finalization. (not a shared helper in @internal/frontend (core-plugin-api cannot import it); not a numeric version counter (a boolean is enough because the signal fires once)) — At most one extra render per mounted hook, none when finalized at mount, no missed signal for components that mount during finalization, unsubscribe on unmount.
- Legacy hook value during bootstrap (FR-3): A module-level constant `bootstrapRouteFunc = () => ''` in packages/core-plugin-api/src/routing/useRouteRef.tsx, returned (cast to `RouteFunc<Params>`) only when the route resolution API path was taken, the ref is non-optional, the resolved value is undefined, and the `finalized` boolean from the private hook (the same value that keyed the memo) is false. With `finalized` true the existing `throw new Error(`No path for ${routeRef}`)` is kept. (not returning undefined (breaks the non-optional overload types and callers that call the result); not calling `isFinalized()` again at the throw site (it is not necessarily the value the memoized resolution used)) — A banner that calls the link during render keeps rendering with an empty link until finalization, then gets the real one.
