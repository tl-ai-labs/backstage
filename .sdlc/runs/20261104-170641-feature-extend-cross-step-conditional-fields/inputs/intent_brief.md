# Intent Brief — feature-extend — Cross-step conditional fields in the Scaffolder form wizard

## Context
Seed: "Let a Scaffolder template show, hide or require fields based on answers given in an earlier step of the form wizard."

Module: the Scaffolder form wizard, in `plugins/scaffolder-react` (Stepper, per-step schema extraction and validation, review step) and `plugins/scaffolder` (template form wiring and the template editor preview). Requested in backstage/backstage#31895. A previous attempt (PR #35196) was closed unmerged.

Today each step's rjsf `Form` receives only that step's schema (`Stepper.tsx`), `createAsyncValidators` validates only the active step's `mergedSchema`, and `ReviewState`'s `findSchemaForKey` (`ReviewState/util.ts`) resolves `dependencies` against that step's own keys. So JSON Schema `dependencies` and `if`/`then` conditions can only see properties declared in the same step. The template editor preview (`TemplateEditorForm`) renders the same `Stepper`, so a fix in scaffolder-react reaches it as well.

Run settings (Gate 0): auth mode `vendor`; policy `argon4-plus-flash38`; test command exactly `CI=true yarn test plugins/scaffolder-react plugins/scaffolder && yarn tsc && yarn lint:all`; `.gitignore` left unchanged (`.sdlc/` is already ignored through `.git/info/exclude`).

## Goal
Conditional fields (JSON Schema `dependencies`, `if`/`then`/`else`, `allOf` of conditions) in one step can depend on answers given in an earlier step, not only the same step.

Example: step 1 asks "Is this a mobile SDK?" (boolean); step 2 shows SDK-specific fields only when the answer is Yes.

- Before: the step-2 SDK fields show regardless of the step-1 answer (or never show).
- After: the step-2 fields appear only when step 1 was answered Yes, their `required` validation applies only then, and the Review step lists them only in that case.

## Acceptance criteria
1. React Testing Library tests on the Stepper show that a step-2 field appears only when a step-1 flag is set.
2. The step-2 field's `required` validation applies only when the step-1 flag is set; with the flag unset, step 2 can be submitted without it.
3. Going back to step 1 and changing the flag removes the step-2 field (and its value) from the Review step.
4. Existing same-step conditions, per-step validation, back-navigation and the Review step keep working; all existing Stepper, ReviewState and schema tests pass.
5. The run's test command passes, exactly: `CI=true yarn test plugins/scaffolder-react plugins/scaffolder && yarn tsc && yarn lint:all`. API reports are regenerated if public API changes.
6. Template-author docs describe cross-step conditions with a worked example.
7. A changeset covers the published packages whose code changes.

## Non-goals
- Changing the backend template parameter validation in `plugins/scaffolder-backend`.
- Changing the template YAML format beyond standard JSON Schema `dependencies` / `if`-`then`-`else`.
- Redesigning the Stepper UI, step navigation, or the legacy (non-`next`) form.
