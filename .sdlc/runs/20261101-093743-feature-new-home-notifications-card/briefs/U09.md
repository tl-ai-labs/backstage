### U08 — create `plugins/notifications/src/components/UnreadNotificationsCard/UnreadNotificationsCard.tsx` (codegen)

Behaviour: Card content listing the signed-in user's latest unread notifications, each with a deep link and mark-as-read, refreshed by signals or, when the signal API is not installed, by a timer.

Rules:
1. Module constants `MaxItems = 5` and `PollIntervalMs = 60000`, named like `ThrottleDelayMs` on the notifications page. `RefreshActions` lists 'new_notification', 'notification_read' and 'notification_unread'.
2. Fetch with `useNotificationsApi<GetNotificationsResponse>` calling `api.getNotifications({ read: false, limit: MaxItems, sort: 'created', sortOrder: 'desc' })`, with no severity filter and no offset, and take `value`, `error`, `loading` and `retry`.
3. `const { lastSignal, isSignalsAvailable } = useSignal<NotificationSignal>('notifications');` then `const [polls] = useState(!isSignalsAvailable);`, so the choice is made once at mount and never changes.
4. `const [refresh, setRefresh] = useState(false);` One effect with deps `[refresh, retry, loading]` does `if (refresh && !loading) { retry(); setRefresh(false); }`. It is the only caller of `retry`, so fetches never overlap and a request made during a fetch runs once after it.
5. An effect on `lastSignal` calls `setRefresh(true)` only when `lastSignal.action` is in `RefreshActions`. Nothing else is read from the signal.
6. An effect with deps `[polls]` returns `undefined` with no timer when `polls` is false; when true it runs `setInterval(() => setRefresh(true), PollIntervalMs)` and clears it in its cleanup. No other code starts or stops that timer, and nothing reads the signal connection. No `setTimeout` and no throttle.
7. `markAsRead(id)` calls `notificationsApi.updateNotifications({ ids: [id], read: true })`. On success, and only if `isMounted()` from `useMountedState` ('react-use/esm/useMountedState'), add the id to `markedReadIds` state (a `Set`) and call `setRefresh(true)`. On rejection, `toastApi.post({ title: t('unreadNotificationsCard.errors.markAsReadFailed'), status: 'danger' })`; the item stays.
8. An effect on `value` resets `markedReadIds` to an empty `Set`. The shown list is `value.notifications` without ids in `markedReadIds`.
9. Render in this order: `error` gives `<ResponseErrorPanel error={error} />`; no `value` yet gives `<Progress />`, both from '@backstage/core-components'; an empty list gives `<Text variant="body-medium" color="secondary">` with `t('unreadNotificationsCard.empty')`; otherwise the list. A refresh that has a previous `value` shows no loading state.
10. List: a column `Flex`; each item a row `Flex` with `justify="between"` and `align="center"`, keyed by id, holding `SeverityIcon` from '../NotificationsTable/SeverityIcon' (not `NotificationIcon`, which calls `useApp`), the title and created time as in NotificationsTable, and the action.
11. The title is a core-components `Link` to `` `${notificationsRoute}?id=${encodeURIComponent(notification.id)}` ``, with `notificationsRoute` from `useRouteRef(rootRouteRef)()` ('@backstage/core-plugin-api', '../../routes').
12. The action is `ButtonIcon` in `TooltipTrigger` with `Tooltip`, label and tooltip `t('unreadNotificationsCard.markAsRead')`, `icon={<RiCheckboxCircleLine size={16} />}`, `variant="secondary"`, `onPress` calling `markAsRead`.
