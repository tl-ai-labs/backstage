## Conventions

- Every new .ts or .tsx file must start with the standard Backstage Apache 2.0 license header dated 2026; existing files must preserve their current copyright year.
- Use TypeScript with explicit types matching @backstage/types (JsonObject, JsonValue) and @rjsf/utils (UiSchema, FieldValidation).
- Do not modify public or @alpha exported signatures in @backstage/plugin-scaffolder-react so report.api.md and report-alpha.api.md stay unchanged.
- React Testing Library tests must use screen and findBy*/getBy*/queryBy* queries rather than waitFor where possible, must not add data-testid attributes, and must prefer fewer, thorough user-journey tests.

## Decisions

- Where shared cross-step schema resolution helpers live: Export resolveConditionalSchema, resolveStepSchema, collectCrossStepHiddenKeys, and collectAllSchemaKeys from plugins/scaffolder-react/src/next/lib/schema.ts without re-exporting them from src/next/lib/index.ts (not Re-exporting from src/next/lib/index.ts (would alter @alpha public API report); not Creating a separate helper file (unnecessary extra file when lib/schema.ts already owns step schema extraction)) — Keeps all schema extraction and conditional resolution in lib/schema.ts while preserving report.api.md and report-alpha.api.md unchanged.
- Condition evaluation semantics for JSON Schema if and dependencies branches: Strip undefined values from formData and normalize condition schemas so properties keys without a 'not' keyword are added to required before calling Draft07.isValid from json-schema-library (not Calling Draft07.isValid or AJV on raw condition schemas without required (causes undefined/unanswered fields to vacuously pass properties constraints in Draft-07)) — In JSON Schema Draft-07, properties constraints pass vacuously when a key is absent; requiring positive condition keys ensures unanswered fields do not trigger then/oneOf branches.
- Distinguishing cross-step conditions from same-step conditions: Treat a dependency key or if/allOf/oneOf/anyOf condition as cross-step when its controlling property is not in the current step's own top-level properties, resolving and removing cross-step conditions while leaving same-step conditions intact in the step schema (not Resolving both same-step and cross-step conditions into static properties (would break RJSF live same-step toggling and same-step hidden value retention)) — RJSF natively handles same-step conditions when the trigger property is in the current step's properties, whereas cross-step triggers are fixed while on a later step.
- Selective clearing of hidden field values in Stepper stepsState: Prune keys in collectCrossStepHiddenKeys(steps, nextState) inside Stepper handleChange and handleNext by removing keys defined in a step's mergedSchema that are absent from any step's cross-step-resolved mergedSchema (not Enabling RJSF liveOmit/omitExtraData globally (would strip values from other steps and clear same-step hidden fields); not Pruning only on handleCreate (would leave stale cross-step hidden values visible or retained when navigating between steps)) — Cross-step-resolved mergedSchema retains all same-step conditional branches and active cross-step branches, so only fields from inactive cross-step branches are removed.
- ReviewState handling of conditional fields and findSchemaForKey: Resolve each step's mergedSchema with resolveConditionalSchema in findSchemaForKey and processSchema, return the original step object from findSchemaForKey when matched, and in ReviewState omit keys where findSchemaForKey returns null if the key belongs to collectAllSchemaKeys(props.schemas) (not Returning a cloned step object from findSchemaForKey (breaks reference-equality checks in util.test.ts); not Unconditionally returning [] when findSchemaForKey returns null (breaks ReviewState.test.tsx cases where schemas is empty or formState has undeclared keys)) — Preserves backward compatibility for undeclared keys and reference equality in findSchemaForKey while hiding inactive conditional fields and resolving active conditional schemas.

3. 3. Add internal helper normalizeConditionSchema(schema: JsonObject): JsonObject that clones schema, sets type to 'object' when properties is an object, adds every key of properties whose value is an object without a 'not' property into required, and recurses on nested properties, allOf, anyOf, and oneOf.

6. 6. Add internal helper getConditionKeys(conditionSchema: JsonObject): string[] that collects property names referenced in conditionSchema.properties, conditionSchema.required, and recursively in conditionSchema.allOf, conditionSchema.anyOf, conditionSchema.oneOf, and conditionSchema.not.
7. 7. Export collectAllSchemaKeys(steps: Pick<ParsedTemplateSchema, 'mergedSchema'>[]): Set<string> that traverses each step's mergedSchema (properties, dependencies, then, else, allOf, oneOf, anyOf) and returns the set of all defined property keys (excluding condition-only keys inside 'if' blocks).
8. 8. Export resolveConditionalSchema(schema: JsonObject, formData: JsonObject, priorStepKeys: Set<string> = new Set()): JsonObject that deep-clones schema via parse(stringify(schema)), determines ownKeys = new Set(Object.keys(cloned.properties ?? {})), and resolves cross-step conditions against formData while leaving same-step conditions (where all controlling keys are in ownKeys) untouched.
9. 9. In resolveConditionalSchema, for each [depKey, depValue] in cloned.dependencies: if ownKeys.has(depKey), keep it in cloned.dependencies; otherwise remove depKey from cloned.dependencies (deleting cloned.dependencies if empty) and evaluate depValue with excludeKeys = new Set([depKey, ...Array.from(priorStepKeys).filter(k => !ownKeys.has(k))]): (a) if Array.isArray(depValue) and isDependencyTruthy(formData[depKey]), add string entries not in excludeKeys to cloned.required; (b) if isObject(depValue) with oneOf or anyOf array, for each branch object check if branch.properties has depKey (if so evaluate matchesSchemaCondition({ type: 'object', properties: { [depKey]: branch.properties[depKey] } }, formData), else if isObject(branch.if) evaluate branch, else check isDependencyTruthy(formData[depKey])), and for matching branches recursively resolve and merge their properties and required (excluding excludeKeys) into cloned (stopping after first match for oneOf); (c) if isObject(depValue) with allOf array, recursively resolve each item and merge into cloned; (d) if isObject(depValue) with if, evaluate matchesSchemaCondition(depValue.if, formData) to recursively resolve and merge depValue.then or depValue.else into cloned; (e) if isObject(depValue) has direct properties or required without oneOf/anyOf/if and isDependencyTruthy(formData[depKey]), merge them into cloned (excluding excludeKeys).
10. 10. In resolveConditionalSchema, when isObject(cloned.if) and getConditionKeys(cloned.if).some(k => !ownKeys.has(k)): remove if, then, and else from cloned, evaluate matchesSchemaCondition(cloned.if, formData), and recursively resolve and merge either then (when true) or else (when false) into cloned (excluding keys in priorStepKeys not in ownKeys). Similarly, for cloned.allOf, resolve and merge any item whose if or dependencies or oneOf/anyOf references a key not in ownKeys, keeping only same-step items in cloned.allOf (deleting cloned.allOf if empty). For top-level cloned.oneOf or cloned.anyOf whose branches constrain a key in priorStepKeys not in ownKeys, evaluate the matching branch(es) against formData, merge their properties and required (excluding priorStepKeys not in ownKeys) into cloned, and delete the resolved oneOf/anyOf.
11. 11. Export resolveStepSchema(step: ParsedTemplateSchema, formData: JsonObject, priorStepKeys: Set<string> = new Set()): ParsedTemplateSchema that computes resolvedMerged = resolveConditionalSchema(step.mergedSchema, formData, priorStepKeys), runs extractSchemaFromStep(resolvedMerged) to get { schema: extractedSchema, uiSchema: extractedUiSchema }, strips title from extractedSchema, filters extractedSchema.properties to exclude any key that was present in step.mergedSchema.properties but filtered out of step.schema.properties by featureFlags (or whose extractedUiSchema[key]?.['ui:backstage']?.featureFlag is in step.uiSchema and was filtered out), ensures extractedSchema.type is 'object' and extractedSchema.properties is an object when properties were resolved or !extractedSchema.dependencies, merges step.uiSchema with extractedUiSchema (and if Array.isArray(mergedUiSchema['ui:order']) without '*', appends any new keys in extractedSchema.properties not yet in 'ui:order'), and returns { ...step, mergedSchema: resolvedMerged, schema: extractedSchema, uiSchema: mergedUiSchema }.
12. 12. Export collectCrossStepHiddenKeys(steps: ParsedTemplateSchema[], formData: JsonObject): Set<string> that iterates steps in order while accumulating priorStepKeys: for each step, collects stepCandidateKeys (keys in collectAllSchemaKeys([step]) that are not in priorStepKeys, or are in step.mergedSchema.properties), resolves the step via resolveConditionalSchema(step.mergedSchema, formData, priorStepKeys), collects activeStepKeys = collectAllSchemaKeys([{ mergedSchema: resolvedMerged }]), adds stepCandidateKeys to priorStepKeys, and after checking all steps returns the set of all candidate keys that are not in any step's activeStepKeys.
