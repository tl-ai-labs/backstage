# Requirements — bugfix — useRouteRef in app root elements before finalization

Run: `20261109-123500-bugfix-routeref-app-root` · intent: bugfix (reproduce + diagnose) · upstream issue: backstage/backstage#35932

## Reproduction

1. Create an app with `createSpecializedApp` / `prepareSpecializedApp` (new frontend system) containing:
   - a page extension (`PageBlueprint`) that declares a `routeRef` and is attached under `app/routes` (that is, under `app/root.children`);
   - an app root element (`AppRootElementBlueprint`, attached to `app/root.elements`) whose component calls `useRouteRef(thatPageRouteRef)` and renders a link to the returned route.
2. Render the bootstrap app (the phase before finalization, for example while sign-in is shown), then finalize the app and render it again.
3. Observed: during the bootstrap phase the root element cannot resolve the page's route ref. Through the legacy `@backstage/core-plugin-api` `useRouteRef` bridge this throws `No path for routeRef{...}`, and the app shows an extension error box in place of the root element. Through the new `@backstage/frontend-plugin-api` `useRouteRef`, the hook returns `undefined`. After finalization the hook still does not produce the resolved link, because its memoized result is keyed only on the API instance, the ref and the pathname, and the root element keeps its bootstrap instance.

## Diagnosis (to be confirmed by the architect against the code)

- `createBootstrapApp` (`treeLifecycle.tsx`) instantiates the tree with `stopAtAttachment` at `app/root.children`, so page routes are not instantiated in the bootstrap phase. `app/root.elements` are instantiated at bootstrap and keep their instances across finalization.
- `instantiateAndInitializePhaseTree` (`phaseApis.tsx`) calls `RouteResolutionApiProxy.initialize` with route info extracted from the bootstrap-visible tree only. That route info has no paths for routes under `children`.
- `RouteResolver.resolve` returns `undefined` for a target ref without a path. The legacy bridge turns that into `throw new Error('No path for ...')` for non-optional refs. In both hooks, the `useMemo` result is never recomputed when the proxy's delegate is replaced at finalization, so a component that rendered during bootstrap is not re-resolved.

## In scope

1. Root elements and other components rendered before finalization can call `useRouteRef` for page routes that are not yet known without crashing the app.
2. Once the app is finalized, those components re-render with the resolved route, with no extra render loops.
3. Both the new (`@backstage/frontend-plugin-api`) and the legacy-bridge (`@backstage/core-plugin-api`) `useRouteRef` behave this way when backed by the new frontend system's route resolution.
4. A regression test in `packages/frontend-app-api/src/wiring/createSpecializedApp.test.tsx` that fails before the fix.
5. A changeset for every affected published package, and documentation of the behavior.

## Out of scope

1. The rest of the old frontend system (`packages/core-app-api/**`, `packages/core-plugin-api/**` beyond `src/routing/useRouteRef.tsx`).
2. Changing which extensions are instantiated in the bootstrap phase.
3. Hand-editing API reports (they are regenerated by `yarn build:api-reports` only).

## Functional requirements

- **FR-1** — During the bootstrap phase, resolving a route ref whose route is not yet known (it is under `app/root.children`) must not throw from the route resolution layer. The new `useRouteRef` returns `undefined`, as it already documents for refs that cannot be resolved.
- **FR-2** — During the bootstrap phase, the legacy `@backstage/core-plugin-api` `useRouteRef`, when backed by the new frontend system's route resolution, must not throw `No path for ...` for a route that becomes known only at finalization. It must not crash the root element that calls it.
- **FR-3** — When the app is finalized and the route resolution API gets its complete route info, every mounted component that called `useRouteRef` re-resolves and re-renders with the now-resolvable route function. A component that keeps its bootstrap instance (an app root element) must show the correct link after finalization.
- **FR-4** — The re-resolution must be driven by a change in route resolution state (for example a subscription or version on the route resolution API), not by polling or unconditional re-renders. It must not cause render loops, and it must not re-render consumers when nothing changed.
- **FR-5** — Behavior for apps that are already finalized (`createSpecializedApp`, and components rendered under `app/root.children`) is unchanged: refs resolve as before, and a ref that is unbound or unknown after finalization behaves exactly as today. In the legacy hook that means it still throws `No path for ...` for a non-optional ref that cannot be resolved once the app is finalized.
- **FR-6** — Any public API addition (for example an optional subscription method on `RouteResolutionApi`) must be optional, so that existing custom implementations of `RouteResolutionApi` keep compiling and working.
