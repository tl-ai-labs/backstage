# Change plan — 20261101-153026-docs-catalog-model-tsdoc

Rendered by code from the accepted change spec (change-spec.json). Change the spec's section files and check them again; do not edit this file.

## Conventions

- Comments only: every source edit adds TSDoc comment lines and nothing else; no code, type, import, export, blank-line or copyright-header change.
- TSDoc blocks are multi-line: a `/**` line, ` * text` lines, a ` */` line, indented to the declaration they document (2 spaces inside an interface or class, none at top level).
- Wrap comment text so no line exceeds 80 columns; Prettier (`@backstage/cli/config/prettier`) does not rewrap comments, so wrap by hand.
- Sentence case, full stops, plain present tense, as in packages/catalog-model/src/entity/Entity.ts and src/validation/CommonValidatorFunctions.ts.
- Write `@param name - description` with the `-` separator; a blank ` *` line separates the summary, `@remarks` and the tag lines.
- Never add, remove or move a release tag (`@public`, `@alpha`); member comments carry no release tag.
- Put every `<...>`, `{`, `}`, `@`, character class and code symbol inside backticks so TSDoc does not read it as HTML, an inline tag or a block tag.
- No `{@link}` tags in new comments; name other members in backticks instead.
- Use the exact comment text given in each unit's rules and sites; only the line wrapping is the typist's.

## Decisions

- Target set: The 45 `(undocumented)` markers in packages/catalog-model/report.api.md, across the 15 source files of FR-1 to FR-4. (not Also documenting Validators members, CompoundEntityRef fields and groupEntityV1alpha1Validator; not Clearing the alpha-only markers in report-alpha.api.md) — The report is authoritative and does not mark the other symbols; alpha markers are out of scope unless they fall in the same edits (the kind members do).
- Kind interface member comments: One block above each of `apiVersion`, `kind` and `spec`, inserted directly above the member line with no blank lines added; existing nested `spec` fields stay uncommented. (not Blank lines between members as in Entity.ts; not Comments on each nested spec field) — AC-4 requires the diff to add only comment lines, and FR-1 limits the change to the three flagged members.
- Type guard comments: Fill the existing `/** @public */` block of each guard: summary paragraph, blank ` *` line, `@param entity - The entity to check`, blank ` *` line, then the existing ` * @public` line kept as is. No `@remarks` in any new comment of this run. (not A new block above the existing one; not Adding `@returns`; not `@remarks` sections (no neighbouring member or guard uses one)) — One TSDoc block per declaration; the `@param` mirrors src/entity/ref.ts and the boolean result is implied by the summary.
- Validator and policy method comments: A new block above each static method or `enforce` method, ending with `@param value - The value to check` (validators) or `@param entity - The entity to enforce the policy on` (policies). (not `@returns` and `@throws` tags) — Matches CommonValidatorFunctions member style; return and failure behaviour is stated in the prose as FR-3 and FR-4 ask.
- API reports: report.api.md and report-alpha.api.md are regenerated by the project check `yarn build:api-reports packages/catalog-model`, never typed. — API Extractor owns the reports; hand edits would drift.
