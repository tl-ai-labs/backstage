# Requirements — docs — TSDoc for the 45 undocumented items in @backstage/catalog-model

Run: `20261029-docs-catalog-model-tsdoc` · Intent: `docs` (scoped: "what docs?") · Package:
`@backstage/catalog-model` (packages/catalog-model, v1.10.2)

`packages/catalog-model/report.api.md` carries 45 `// (undocumented)` markers today (counted at run start).
This run documents exactly those 45 items in place, in the package source, regenerates the API reports, and
adds a patch changeset.

## In scope

1. TSDoc on the `apiVersion`, `kind` and `spec` members of the 8 kind interfaces
   `ApiEntityV1alpha1`, `ComponentEntityV1alpha1`, `DomainEntityV1alpha1`, `GroupEntityV1alpha1`,
   `LocationEntityV1alpha1`, `ResourceEntityV1alpha1`, `SystemEntityV1alpha1`, `UserEntityV1alpha1`
   (src/kinds/\*EntityV1alpha1.ts) — 24 items.
2. TSDoc on the 8 type guards `isApiEntity`, `isComponentEntity`, `isDomainEntity`, `isGroupEntity`,
   `isLocationEntity`, `isResourceEntity`, `isSystemEntity`, `isUserEntity` (src/entity/conditions.ts) —
   8 items.
3. TSDoc on the 8 static methods of `KubernetesValidatorFunctions` (`isValidApiVersion`, `isValidKind`,
   `isValidObjectName`, `isValidNamespace`, `isValidLabelKey`, `isValidLabelValue`,
   `isValidAnnotationKey`, `isValidAnnotationValue`) (src/validation/KubernetesValidatorFunctions.ts) —
   8 items.
4. TSDoc on the `enforce` method of the 5 entity policies `DefaultNamespaceEntityPolicy`,
   `FieldFormatEntityPolicy`, `GroupDefaultParentEntityPolicy`, `NoForeignRootFieldsEntityPolicy`,
   `SchemaValidEntityPolicy` (src/entity/policies/\*.ts) — 5 items.
5. Regenerated `packages/catalog-model/report.api.md` and `report-alpha.api.md`, produced only by
   `yarn build:api-reports`.
6. A new patch changeset `.changeset/catalog-model-tsdoc.md` for `@backstage/catalog-model`.

## Out of scope

1. The 25 `(undocumented)` markers in `report-alpha.api.md` that are not re-exports of the 45 items above
   (AI resource kinds, `McpServerApiEntity`, `CatalogModelKindRootSchema`, etc.).
2. Nested `spec.*` sub-fields that the report does not flag.
3. Any code, signature, type, or release-tag change; any runtime behaviour change.
4. Tests, README, `/docs`, `docs/releases/**`, other packages, lint/prettier/tsconfig files.
5. Hand edits to `report*.api.md` (regenerated by the tool only).

## Functional requirements

### Module: kinds (src/kinds)

- **FR-1** Each of the 8 kind interfaces gets a TSDoc block on `apiVersion` stating the accepted API
  versions as declared in the type (`backstage.io/v1alpha1` or `backstage.io/v1beta1`).
- **FR-2** Each of the 8 kind interfaces gets a TSDoc block on `kind` naming the literal kind value as
  declared in the type (for example `Component`).
- **FR-3** Each of the 8 kind interfaces gets a TSDoc block on `spec` describing what the spec holds for that
  kind, consistent with the fields the type declares and the kind's JSON schema in
  `src/schema/kinds/*.schema.json`; it must not claim a field is required or optional contrary to the type.

### Module: conditions (src/entity/conditions.ts)

- **FR-4** Each of the 8 guards gets a summary, a `@param entity` line and a `@returns` description,
  stating the check exactly as implemented (e.g. a case-insensitive comparison of `entity.kind` against the
  kind name, if that is what the code does) and that it narrows the type to the matching interface.
  The existing `@public` tag stays, unchanged and last.

### Module: validation (src/validation/KubernetesValidatorFunctions.ts)

- **FR-5** Each of the 8 static methods gets a summary and `@param value` / `@returns` lines describing the
  rule it applies as implemented (character set, length limits, prefix handling, type checks such as
  non-string input returning `false`), verified against the method body and any helper it calls.

### Module: policies (src/entity/policies)

- **FR-6** Each of the 5 `enforce` methods gets TSDoc describing its behaviour as implemented: what it
  checks or fills in, what it returns (the same entity, a modified copy, or `undefined` where the
  implementation does so), and when it throws (and with what error type, if the code names one).
  Behaviour must be read from the method body, not inferred from the class name.

### Module: release

- **FR-7** `.changeset/catalog-model-tsdoc.md` is a new `patch` changeset for `@backstage/catalog-model`
  only, written for adopters in plain language (documentation added to the entity kind types, kind type
  guards, Kubernetes-style validators and entity policies), with no references to internal code symbols.
- **FR-8** `packages/catalog-model/report.api.md` and `report-alpha.api.md` are regenerated with
  `yarn build:api-reports` after the source edits.

## Non-functional requirements

- **NFR-1** The `src/` diff is comment-only: every added or changed line is inside a `/** ... */` block. No
  code token, signature, import, or existing comment changes; existing release tags untouched.
- **NFR-2** Style matches the package's existing TSDoc (reference: `src/kinds/ComponentEntityV1alpha1.ts`,
  existing method docs in `KubernetesValidatorFunctions.ts` and the policy classes): short sentence-case
  summaries ending with a period, `{@link ...}` for cross-references, and the doc style guide at
  `/docs/contribute/doc-style-guide.md`.
- **NFR-3** Every statement in a new comment is accurate against the implementation it documents.
- **NFR-4** Edited files pass `yarn prettier --check` (prettier run only on changed files).
- **NFR-5** No copyright-year change on any existing file.
