## Decisions

- How bootstrap route resolution learns about pages under the deferred app/root.children subtree: During bootstrap only (when stopAtAttachment is passed), instantiateAndInitializePhaseTree walks the deferred subtree and, for each enabled node whose extension declares a coreExtensionData.routePath or coreExtensionData.routeRef output, instantiates that node's subtree detached (writeNodeInstances: false, reuseExistingInstances: false) with an empty API holder and a throwaway error collector; the resulting instances are passed to extractRouteInfoFromAppNode as a fallback lookup used only where node.instance is undefined. (not Instantiating the whole deferred subtree in place: runs app/layout and other non-route factories twice and breaks the existing appLayoutFactory call-count test; not Instantiating with the real phase APIs: would materialize APIs during bootstrap and change which deferred API overrides finalization accepts; not Reporting detached failures to the app collector: would surface spurious EXTENSION_FACTORY_ERROR entries in finalized errors; not Changing the bootstrap boundary or useRouteRef: out of scope) — Only route-bearing extensions are run, without side effects on the live tree, APIs or error reporting, and the extracted paths and parents come from the same edge walk the finalized app performs, so the bootstrap result equals the finalized one.
- Stale route functions held by app/root.elements after finalization: RouteResolutionApiProxy.resolve returns a wrapper RouteFunc that remembers the delegate it was resolved with; when called after the proxy has been re-initialized with a new delegate it re-resolves the same ref and options against the current delegate and uses that result, falling back to the original function when the current delegate cannot resolve the ref. (not Giving the proxy a new identity at finalization: requires changing FrontendApiRegistry caching and AppRouter's getRouteObjects access, both outside the allowlist; not Doing nothing beyond the bootstrap extraction: leaves predicate-dependent routes stale in preserved elements) — useRouteRef memoizes on the proxy object, which never changes identity, so the returned function itself must follow the finalized resolver; while the delegate is unchanged it calls the original function directly, so existing resolution is unchanged.
- Reproducing test placement and hook choice: One new it() in the existing describe('prepareSpecializedApp') block of createSpecializedApp.test.tsx, inserted after the 'should synchronously finalize feature flag predicates without sign-in' case, using the frontend-plugin-api useRouteRef already imported there and rendering 'link: <path or none>'; the red check runs only that case with jest -t. (not Using the core-plugin-api useRouteRef: needs a type cast between route ref types and a new import; not A new test file: the requirements place the test in createSpecializedApp.test.tsx) — On the current code the element renders 'link: none' during bootstrap, so the case fails before the fix and passes after it, while the -t filter keeps the red check green on the file as it is now.

### U03 — edit `packages/frontend-app-api/src/wiring/phaseApis.tsx` (codegen)

Behaviour: Bootstrap route resolution includes route paths and refs from the deferred app/root.children subtree, and route functions handed out before finalization follow the finalized resolver.

Rules:

1. 1. Add a module-level const EMPTY_API_HOLDER: ApiHolder = { get() { return undefined; } }; and a non-exported function collectDeferredRouteInstances(options: { tree: AppTree; extensionFactoryMiddleware?: ExtensionFactoryMiddleware; stopAtAttachment(ctx: { node: AppNode; input: string }): boolean }): Map<AppNode, AppNodeInstance>, both placed between instantiateAndInitializePhaseTree and setIdentityApiTarget.
2. 2. collectDeferredRouteInstances walks from options.tree.root over node.edges.attachments with a visited Set; for each input where options.stopAtAttachment({ node, input }) is true, every child of that input is handed to the deferred visit instead of the normal walk.
3. 3. The deferred visit, with its own visited Set, skips a node and its whole subtree when node.spec.disabled is true or node.spec.if !== undefined (predicate-gated pages are only resolvable after finalization).
4. 4. For any other deferred node that has no instance and whose extension declares a coreExtensionData.routePath or coreExtensionData.routeRef output, call instantiateAppNodeSubtree({ rootNode: node, apis: EMPTY_API_HOLDER, collector: createErrorCollector(), extensionFactoryMiddleware: options.extensionFactoryMiddleware, writeNodeInstances: false, reuseExistingInstances: false }) and, when the result has an instance, store it in the map under the original node; a failed instantiation is ignored and leaves the node out.
5. 5. Detect declared outputs with toInternalExtension(node.spec.extension): for version 'v1' look at Object.values(internal.output), for 'v2' at internal.output, comparing each ref.id with coreExtensionData.routePath.id and coreExtensionData.routeRef.id; nodes without such outputs are never instantiated, so app/layout, app/routes and other content factories do not run during bootstrap.
6. 6. The deferred visit then continues into every child of every input of the node, so nested pages and sub-pages are collected too.
7. 7. In instantiateAndInitializePhaseTree pass the result of collectDeferredRouteInstances({ tree, extensionFactoryMiddleware, stopAtAttachment }) as the third argument of extractRouteInfoFromAppNode only when options.stopAtAttachment is set, and undefined otherwise, so finalization extracts route info exactly as before.
8. 8. RouteResolutionApiProxy.resolve keeps its existing throw when #delegate is unset; otherwise it captures const delegate = this.#delegate, calls delegate.resolve(anyRouteRef, options), and returns undefined when that is undefined.
9. 9. Otherwise resolve returns a new RouteFunc<TParams> that calls the captured function while this.#delegate is still the captured delegate; once the proxy has been re-initialized it resolves the same anyRouteRef and options against the current delegate, caches that result together with the delegate it came from inside the closure, and calls it, falling back to the captured function when the current delegate returns undefined.
10. 10. Add one or two short why-comments: one at the deferred-route collection explaining bootstrap stops at the session boundary while app root elements still need those routes, one at the resolve wrapper explaining useRouteRef memoizes on the proxy instance, which keeps its identity across finalization.
