### U60 — edit `docs/features/software-catalog/life-of-an-entity.md` (docs)

Behaviour: Explains rename timing and orphans in plain terms.

Rules:
1. 1. A rename creates a new entity: a new name is a new row, and nothing links the two unless the new entity lists the old name in `backstage.io/former-names`. Link to `well-known-annotations.md#backstageioformer-names`.
2. 2. The old link redirects only after the old entity is gone, because a normal lookup still finds it. Say why: an orphan is still an entity.
3. 3. With the default `orphanStrategy: delete`, the old entity becomes an orphan the next time its parent is processed, by default every 100 to 150 seconds. The old link keeps showing the orphan until the orphan cleanup removes it, which runs every 30 seconds. The redirect starts once the old entity is gone and the new one has been stitched.
4. 4. With `orphanStrategy: keep`, or while something else keeps the old entity alive, such as another location or provider still emitting it or a file that moved or cannot be read, the redirect does not fire until the old entity is removed by hand, for example with the delete action on the orphan warning, or the cause is fixed. Until then the old entity's own former names also stay claimed, so a name it and the new entity both list is contested.
5. 5. Entity providers delete eagerly, as the next section explains, so there is no orphan stage: the old link shows the normal not-found page until the new entity has been processed and stitched, usually a few seconds, and then redirects.

### U59 — edit `docs/features/software-catalog/well-known-annotations.md` (docs)

Behaviour: Documents the annotation and its rules.

Rules:
1. 1. Start with a YAML example in the style of the section above: `backstage.io/former-names: old-name, team-a/older-name`.
2. 2. Syntax: a comma-separated list of `[<kind>:][<namespace>/]<name>`; kind and namespace default to the entity's own; matching ignores case.
3. 3. Effect: an old entity page or TechDocs link redirects to this entity with a notice. Link to `life-of-an-entity.md#renaming-an-entity`.
4. 4. Who may claim: any entity, in any namespace, for a name of its own kind other than its current name. Backstage cannot prove an entity once held a name, so anyone who can register a location can claim a retired name. Review descriptor changes if that matters to you.
5. 5. Conflicts: an existing entity at the old ref always wins, including an orphan, and the claim waits. When several entities claim one name, nothing redirects and each gets a warning on its status. Invalid entries are skipped with a warning; valid ones still work.
6. 6. Permissions: a redirect happens only if the reader may read the target; otherwise they see the normal not-found page.
7. 7. No chains: list every former name you want honoured.
8. 8. Not changed: `GET /entities/by-name` still returns 404 for a former name, and stored references such as `spec.owner` are not rewritten.
9. 9. Privacy: do not use this to record a person's past name on `User` or `Group` entities.
