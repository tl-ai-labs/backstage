### U59 — edit `docs/features/software-catalog/well-known-annotations.md` (docs)

Behaviour: Documents the annotation and its rules.

Rules:
1. 1. Start with a YAML example in the style of the section above: `backstage.io/former-names: old-name, team-a/older-name`.
2. 2. Syntax: a comma-separated list of `[<kind>:][<namespace>/]<name>`; kind and namespace default to the entity's own; matching ignores case.
3. 3. Effect: an old entity page or TechDocs link redirects to this entity with a notice. Link to `life-of-an-entity.md#renaming-an-entity`.
4. 4. Who may claim: any entity, in any namespace, for a name of its own kind other than its current name. Backstage cannot prove an entity once held a name, so anyone who can register a location can claim a retired name. Review descriptor changes if that matters to you.
5. 5. Conflicts: an existing entity at the old ref always wins, including an orphan, and the claim waits. When several entities claim one name, nothing redirects and each gets a warning on its status. Invalid entries are skipped with a warning; valid ones still work.
6. 6. Permissions: a redirect happens only if the reader may read the target; otherwise they see the normal not-found page.
7. 7. No chains: list every former name you want honoured.
8. 8. Not changed: `GET /entities/by-name` still returns 404 for a former name, and stored references such as `spec.owner` are not rewritten.
9. 9. Privacy: do not use this to record a person's past name on `User` or `Group` entities.

Depends on: U18

Covers: FR-27, AC-11
