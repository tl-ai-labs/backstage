### U10 — create `plugins/catalog-backend/src/database/operations/formerRefs/formerEntityRefs.ts` (codegen)

Behaviour: Keeps an entity's rows in `former_entity_refs` equal to its claims, lists which of its claims others share, and turns problems and conflicts into status items.

Rules:
1. 1. `syncFormerEntityRefs` first selects `former_entity_ref` where `entity_id` matches. That SELECT is the only statement when nothing differs, so an entity with no annotation and no rows does no write.
2. 2. It then deletes rows for refs no longer wanted with `where({ entity_id }).whereIn('former_entity_ref', chunk)`, and inserts missing rows with `.insert(rows).onConflict(['entity_id', 'former_entity_ref']).ignore()`, each in `lodash.chunk` batches of 50. Rows hold `entity_id`, `entity_ref` and `former_entity_ref`.
3. 3. `listContestedFormerRefs` returns `[]` with no query when `formerRefs` is empty. Otherwise it selects distinct `former_entity_ref` where the ref is in `formerRefs` and `entity_id` differs from `entityId`, in batches of 200, and returns the refs sorted, so a hash over them is stable.
4. 4. `getFormerRefStatusItems` calls `parseEntityFormerRefs(entity)`. With no `formerRefs` and no `problems` it returns `[]` with no query.
5. 5. Each problem becomes an item with message text `Ignored former name '<entry>': <reason>`. Each ref from `listContestedFormerRefs` becomes an item with text `Former name '<ref>' is claimed by more than one entity, so it does not redirect`. No message names another entity.
6. 6. Items have `type: ENTITY_STATUS_CATALOG_PROCESSING_TYPE`, `level: 'warning'`, `message: 'InputError: ' + text` and `error: { name: 'InputError', message: text }`, the shape `performStitching` gives errors.
7. 7. Nothing here logs.
