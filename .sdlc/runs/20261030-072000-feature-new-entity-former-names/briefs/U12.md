### U12 — create `packages/catalog-client/src/resolveFormerEntityRef.ts` (codegen)

Behaviour: Resolves a possibly-former entity ref to the live entity now claiming it, composed entirely from the existing CatalogApi.queryEntities member so no interface member is added anywhere.

Rules:
1. 1. Export the discriminated-union result type `FormerEntityRefResolution` with exactly two arms: `{ status: 'resolved'; entity: Entity; formerEntityRef: string }` and `{ status: 'unknown' }`. No third arm, and no arm that carries a fabricated entity. Mark it `@public`.
2. 2. Export one async function, `resolveFormerEntityRef(catalogApi, formerEntityRef, options?)`, returning `Promise<FormerEntityRefResolution>`. `catalogApi` is typed `CatalogApi` and is the FIRST parameter — this is a free function over an injected client, NOT a member of CatalogApi. Adding a member to CatalogApi, required or optional, is forbidden: CatalogService and CatalogServiceMock mirror it method-for-method from a package outside this change's scope, and plugins/catalog-import casts an object literal directly to CatalogApi.
3. 3. `options` is `{ token?: string } | undefined`, i.e. the existing `CatalogRequestOptions` type, forwarded verbatim to queryEntities so the caller's credentials travel with the request.
4. 4. Parse `formerEntityRef` with parseEntityRef inside a try/catch with no defaulting context. On a throw, return `{ status: 'unknown' }`. STRUCTURAL USER REFUSAL: also return `{ status: 'unknown' }` without issuing any request when the parsed kind lowercases to 'user'.
5. 5. Canonicalize through stringifyEntityRef and build the predicate key as the string `metadata.annotations.backstage.io/former-entity-refs.` followed by the canonical ref. Define that prefix as a module-level const in this file built from ANNOTATION_FORMER_ENTITY_REFS imported from '@backstage/catalog-model', so the literal appears nowhere. This package cannot import the backend's copy of the prefix — catalog-client does not depend on plugins/catalog-backend — so the one shared source of truth is the annotation constant itself.
6. 6. Issue exactly ONE call: `catalogApi.queryEntities({ query: { $all: [ { [key]: true }, { $not: { kind: 'user' } } ] }, limit: 2 }, options)`. Use `limit: 2`, never 1: two is the smallest limit that distinguishes 'exactly one claimant' from 'contested'.
7. 7. Wrap the call in try/catch. On any thrown error — network failure, a backend too old to understand the predicate, anything — return `{ status: 'unknown' }`. This function must never throw and never reject: it sits on a render path.
8. 8. Return `{ status: 'resolved', entity, formerEntityRef }` only when `items.length === 1`. For 0 items (nothing claims it, or the caller may not read the claimant) and for 2 or more (contested), return `{ status: 'unknown' }`. The zero case being identical for 'absent' and 'forbidden' is the whole point: a caller who may not read the target gets the same answer as for a ref that does not exist, because queryEntities already runs through the backend's authorization, which ANDs the permission predicate into the same query.
9. 9. `formerEntityRef` in the resolved arm is the CANONICALIZED ref, so the notice names a stable lowercase form regardless of URL casing.
10. 10. Do NOT call getEntityByRef or getEntitiesByRefs first to check whether the ref is live. The caller invokes this only after its own direct lookup has already missed; a liveness check here would add a round trip to every miss and would duplicate work the caller has already done.
11. 11. TSDoc both exports `@public`, with a `@remarks` block on the function recording: that it never throws; that it must be called only after a direct lookup has missed, which is what makes a live holder of the name win unconditionally; that 'unknown' deliberately conflates absent, forbidden and contested; and that kind: User is refused outright for privacy. Apache 2.0 header with year 2026.
