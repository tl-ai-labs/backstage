### U27 — create `plugins/techdocs/src/reader/components/TechDocsReaderPage/useFormerRefRedirect.ts` (codegen)

Behaviour: When a docs reader URL's entity does not exist, resolves its ref as a former ref and navigates to the renamed entity's docs URL preserving the docs sub-path, query and fragment.

Rules:
1. 1. Export one hook, `useFormerRefRedirect(entityRef: CompoundEntityRef)`, returning `{ shouldShowProgress: boolean }`. Mark it `@internal`: it is not part of the package's public API.
2. 2. Model it directly on the sibling `useExternalRedirect` in this same directory, including its `checkedEntityRef` useRef guard against remount flicker and its `entityKey = stringifyEntityRef(entityRef)` stable dependency. Do not modify useExternalRedirect itself — the two concerns are distinct and must not share one useAsync.
3. 3. Inside a single `useAsync` keyed on `[entityKey, catalogApi]`: first call `catalogApi.getEntityByRef(entityRef)` inside a try/catch. If it returns a truthy entity, return `undefined` — the entity exists, so this hook does nothing and the ordinary docs flow proceeds. This is what keeps genuine 'docs not built' behaviour unchanged: CONTENT_NOT_FOUND for an entity that DOES exist never reaches this code.
4. 4. Only when the entity is absent, call `resolveFormerEntityRef(catalogApi, entityKey)`. On status 'resolved', return the computed target URL plus the former ref; on 'unknown', return `undefined` so the existing behaviour is untouched.
5. 5. Swallow every error from both calls and return `undefined`, exactly as useExternalRedirect does: this is a render path and it must never throw.
6. 6. TARGET URL, preserving the docs sub-path: get `docsRoute = useRouteRef(rootDocsRouteRef)`. Compute `oldBase = docsRoute({ namespace, kind, name })` from the requested ref and `newBase = docsRoute(...)` from the resolved entity's kind, namespace and name, lowercased the way rootDocsRouteRef params are built elsewhere in this plugin. Take `useLocation()`'s pathname; if it starts with `oldBase`, the target is `newBase` plus the remainder after `oldBase`; otherwise `newBase` alone. Append `location.search` and `location.hash` verbatim. This makes a stale /docs/default/component/old-name/some/page land on /docs/default/component/new-name/some/page.
7. 7. In a `useEffect`, when the async value holds a target, call `navigate(target, { replace: true, state: { formerEntityRef } })` — the same navigation-state carrier the catalog redirect uses, so the one notice component serves both. When the async settles with no target, set `checkedEntityRef.current = entityKey` so a sub-page navigation within the same entity does not re-check.
8. 8. `shouldShowProgress` follows useExternalRedirect's formula: true while checking a not-yet-checked entity, or whenever a target exists and navigation is pending.
9. 9. Import resolveFormerEntityRef from '@backstage/catalog-client' (already a dependency of this package), CompoundEntityRef and stringifyEntityRef from '@backstage/catalog-model', catalogApiRef from '@backstage/plugin-catalog-react', and rootDocsRouteRef from '../../../routes'.
