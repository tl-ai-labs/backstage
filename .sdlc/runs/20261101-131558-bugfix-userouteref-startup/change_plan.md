## Decisions

- D-1, the bootstrap placeholder: While the app is not finalized, the core-plugin-api useRouteRef returns one shared module-level function for a non-optional ref that resolves to undefined. It ignores its params, never throws, and returns the literal string '#'. So a React Router <Link to={fn()}>, including the core-components Link, rendered before finalization has an href of the current page: the current pathname with the app base path and without search or hash (at /base/catalog?x=1 the href is /base/catalog). Clicking it stays on that page and drops any search and hash. A plain <a href={fn()}> stays on the page with no reload, navigate(fn()) stays on the current pathname, and `${fn()}/details` gives '#/details', which also stays on the page. After finalization the element re-renders and the link holds the real path. Optional refs still return undefined, and the frontend-plugin-api hook still returns undefined, because both return types allow it. (not '' : react-router 6.30 treats an empty string as a path, so outside any Route, where app root elements render, the link resolves to / and leaves the page, and a plain anchor with an empty href reloads; not the current pathname from useLocation: it has no app base path, so a plain anchor would be wrong on a sub-path deployment; not returning undefined from the core hook: its non-optional return type must stay callable (FR-2)) — '#' is the only value that stays on the current page in every consumer: Link, navigate, a plain anchor and string concatenation.
- D-2, the lifecycle signal: An internal contract with no public API change. packages/frontend-plugin-api/src/apis/definitions/RouteResolutionLifecycle.ts holds the key, the interface and the hook that reads it, and definitions/index.ts does not re-export it. RouteResolutionApiProxy carries a RouteResolutionLifecycle under Symbol.for('@backstage/frontend-plugin-api:route-resolution-lifecycle'). frontend-plugin-api imports that file by package-relative path; core-plugin-api and frontend-app-api import it by relative monorepo path. An API without the key counts as finalized. (not an optional member on RouteResolutionApi, or a new utility API ref: both are public (Gate 1 D-2); not copying the key and reader into each package: the wire contract would live in three places; not a plain Symbol(): each published package bundles its own copy of a relative import, so the key has to be global) — Both hooks already reach the proxy through useApi, so nothing public is needed. A bundled copy of the file in each package still agrees through Symbol.for, and every other RouteResolutionApi keeps today's behaviour (FR-6).
- What finalized means: One-way and per app instance. RouteResolutionApiProxy.markFinalized() runs as the last step of both finalizeFromSessionState and finalizeFromBootstrapError, once the final route info is in place and the root element is confirmed, and it notifies listeners once. (not the second initialize() call: finalize() with a reused session state initializes only once; not leaving the bootstrap-error path unfinalized: tolerance would outlive finalization, against FR-4) — A thrown finalization stays in bootstrap and can retry, so marking last is correct. On the error path a non-optional root element ref throws No path for into its own boundary, which is what that element did on first render before this fix.
- How the hooks observe finalization: useState seeded from isFinalized(), plus a useEffect that re-reads isFinalized() and then subscribes. With no lifecycle the hook returns true, and the effect does nothing. (not useSyncExternalStore: both hook packages allow React 17 in peerDependencies, and package.json is outside the write contract, so the shim cannot be added) — The re-read catches a finalization between render and subscribe (NFR-2), a same-value setState does not re-render (NFR-1), and legacy apps never set state.
- Refreshing the memos: Add `finalized` to the deps of the frontend hook's memo and of both memos in the core hook, each with `// eslint-disable-next-line react-hooks/exhaustive-deps` directly above the deps array line. (not giving the proxy a new identity at finalization: every useApi consumer would see a changed API) — The memo callback does not read `finalized`, so the lint rule calls it unnecessary, yet it is exactly what invalidates the memo. The repo already disables this rule the same way in useBreadcrumbEntries.tsx and useElementFilter.tsx.

8. Return `lifecycle ? finalized : true`, so an API without the signal always counts as finalized.
9. Mark each export `@internal` in its TSDoc.
