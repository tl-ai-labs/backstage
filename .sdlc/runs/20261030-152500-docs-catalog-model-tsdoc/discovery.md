## API reports — the part that matters most for this run

The repo generates API reports with **API Extractor**, driven by `@backstage/repo-tools`:

```
build:api-reports      -> yarn build:api-reports:only --tsc
build:api-reports:only -> backstage-repo-tools api-reports --sql-reports \
                            --allow-warnings '…' -o ae-undocumented,ae-wrong-input-file-type \
                            --validate-release-tags
```

Per package the artifacts are `report.api.md` and `report-alpha.api.md`. Both carry the banner *"Do not edit this file. It is a report generated by API Extractor."* CI regenerates and verifies them (`yarn build:api-reports:only --ci --docs`, then `node scripts/verify-api-reference.js`).

Current undocumented markers in the target: **45** in `report.api.md`, **25** in `report-alpha.api.md`.

Consequences for the TSDoc run:

1. **The API reports will change.** Every TSDoc comment added to a public export removes a `// (undocumented)` marker. Both report files must be inside the write allowlist, or the run must regenerate them with `yarn build:api-reports`. Regeneration is the sanctioned path; hand-editing contradicts the banner and risks drifting from what CI produces.
2. **`ae-undocumented` is in the `-o` omit list**, so missing docs do not fail the build today. This run is additive quality work, not a fix for a red pipeline.
3. **`--validate-release-tags` is active.** Documented public exports must carry a consistent release tag (`@public` / `@alpha` / `@beta` / `@internal`) or `api-reports` errors out. Adding a doc comment without the right tag can turn a silent omission into a hard failure.
4. **`@param` needs a `-` after the parameter name** (`STYLE.md:234`) or API Extractor warns.
5. **A changeset is likely required.** `@backstage/catalog-model` is a non-private package under `/packages`. 39 changesets already exist in `.changeset/` — per project rules, inspect those for existing coverage before adding one, edit `.changeset/*.md` by hand, and never use the changeset CLI.

`STYLE.md` §Documentation Guidelines is the authoritative in-repo TSDoc style source: `function` keyword over arrow functions for exports, no destructured params in public signatures, `@remarks` to split long descriptions, `{@link …}` for references.

## Coexistence risks

- **Cursor rules detected** at `.cursor/rules/backstage-project.mdc` (plus two under `.cursor/rules/tests/`). The plugin will never touch them, but if you have Cursor's auto-lint running on save, changes we make may trigger it.
- **GitHub Copilot instructions** at `.github/copilot-instructions.md` — untouched, but it is a third instruction source overlapping `AGENTS.md`.
- **No custom `.mcp.json`** — nothing registered at project scope to collide with our bundled dispatch server.
- **No Aider config** — no auto-commit git-history tangle from that direction.
- **`.sdlc/` is not in `.gitignore`.** It *is* currently ignored on this machine, but only through `.git/info/exclude` line 7 (`.sdlc/`) — which is local to this clone and never committed. So `git add -A` is safe here, yet any other clone, teammate, or CI checkout would see run artifacts (packets, `changes.md`, `backups/<file>` echoing source) as untracked-but-addable. Gate 0 will offer to add `.gitignore` (append) to this run's allowlist so the exclusion becomes durable and shared. Note `.claude/settings.local.json` and `.claude/worktrees/` *are* already in `.gitignore`, so the pattern of ignoring tool artifacts is established there.
- **Husky `pre-commit` runs `yarn lint-staged`**, which on staged `.ts` runs `eslint --fix` + `prettier --write`, and on staged `.md` runs prettier plus `scripts/check-docs-quality`. Any commit during the run will reformat touched files — expect post-commit diffs that are not ours.
- **Three overlapping instruction files carry hard rules** worth restating to downstream phases: never run `yarn build` / `changesets version` / `release`; always pass a path to `yarn test`; do not update copyright years on existing files; edit `.changeset/` files directly, never via the CLI; never touch ESLint/Prettier/TypeScript config.
