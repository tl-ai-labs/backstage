# Change plan — 20261030-152500-docs-catalog-model-tsdoc

Rendered by code from the accepted change spec (change-spec.json). Change the spec's section files and check them again; do not edit this file.

## Conventions

- Comment-only change: no executable line, signature, type, name, import or declaration order changes in any unit. Only TSDoc comment blocks are added or replaced.
- The Apache 2.0 license header stays byte-identical at the top of every edited file, original year included. Never bump a year.
- Prettier 2 via @backstage/cli/config/prettier: 80-column print width, single quotes, trailing commas. Let the check's fix form reformat rather than hand-wrapping.
- TSDoc prose is third-person declarative ('Checks that...', 'Sets...', 'Narrows...'); the first sentence is short and indexable; never open with 'This function' or an imperative.
- Tag order inside every block: description, then @remarks, then the release tag, then @param, @returns, @throws.
- Every @param uses the form '@param name - description'; the hyphen is required (STYLE.md:234) or API Extractor warns.
- {@link Symbol} for in-package cross-references; '@see https://...' with a bare URL for external specs, matching CommonValidatorFunctions.
- @remarks only where the text runs longer than two lines; a short block is one paragraph with no @remarks.
- Documented members of a type, interface or class carry no release tag of their own; only the enclosing declaration does, and its existing tag is reused verbatim.
- No test file is touched and no test is added. The package's existing 64 suites / 893 tests are the regression check.
- packages/catalog-model/report.api.md and report-alpha.api.md are generated by API Extractor and are never hand-edited; no unit writes them.

## Decisions

- Shape of an added member comment (interface member, class method, static): A multi-line block comment on its own lines directly above the member, as in src/entity/Entity.ts: '/**', ' * text', ' */'. (not The compact single-line form '/** text */') — The compact form is used in this package only for inline nested members such as the parseEntityRef context object; every documented interface member and class member uses the multi-line block.
- Release tag on each added block: Reuse the tag packages/catalog-model/report.api.md already shows for the enclosing declaration; added member blocks carry no tag at all. (not Adding @public to a member block; not Promoting an @alpha declaration to @public) — --validate-release-tags is active in build:api-reports, so a wrong or duplicated tag turns today's silent omission into a hard build failure.
- Editing the existing '/** @public */' blocks in src/entity/conditions.ts: Replace the whole three-line comment block per function with a new block holding description, then @public, then @param entity. (not Inserting description lines before the ' * @public' line and a @param line after it) — One replace site per function keeps tag order correct in one edit and leaves no chance of a stray second comment opener.
- Tag set on the five enforce methods: Description, '@param entity - ...', '@returns ...', and '@throws ...' only on the methods whose own body throws (FieldFormatEntityPolicy, NoForeignRootFieldsEntityPolicy, SchemaValidEntityPolicy). (not @throws on all five; not Description and @param only) — Mirrors the EntityPolicy.enforce block in src/entity/policies/types.ts while staying accurate: DefaultNamespaceEntityPolicy.enforce and GroupDefaultParentEntityPolicy.enforce never throw (GroupDefaultParentEntityPolicy throws from its constructor only).
- Wording for the apiVersion and kind members of the eight kind interfaces: State that the member narrows the inherited Entity field to the literal value(s) this kind accepts, and name those literals. (not Restating the TypeScript type; not Describing apiVersion as a version-negotiation or migration mechanism) — Both members are literal discriminators in the source; the code expresses nothing beyond the accepted literals and must not be given invented semantics.
- Describing KubernetesValidatorFunctions.isValidObjectName: State the literal rule only: a string of 1 to 63 characters that begins and ends with [A-Za-z0-9] and may contain [-_.] in between. No @see. (not Calling it a DNS subdomain name and linking the Kubernetes object-names document; not Calling it a DNS label) — The regex permits uppercase letters, underscores and dots, so it is neither the DNS subdomain nor the DNS label rule the names document describes; no single Kubernetes document matches it, and a wrong @see is worse than none.
- Describing the delegating Kubernetes validators: Describe the rule the delegate actually enforces and cross-reference it with {@link CommonValidatorFunctions.isValidDnsLabel} / {@link CommonValidatorFunctions.isValidDnsSubdomain} / {@link KubernetesValidatorFunctions.isValidObjectName}. (not Describing the rule from the member name; not Only saying that the call is delegated) — isValidNamespace, isValidLabelKey, isValidAnnotationKey, isValidLabelValue and isValidApiVersion all delegate; a reader needs the enforced rule, and the link gives the exact predicate.
- Where the two API reports come from: No unit edits packages/catalog-model/report.api.md or report-alpha.api.md; they are regenerated by the run's acceptance check outside the spec. (not A unit that hand-edits the reports; not A tooling unit that runs yarn build:api-reports) — The files carry API Extractor's do-not-edit banner, and a docs job may hold no tooling unit; regeneration is the person's acceptance step.
- Changeset file name and bump level: A new .changeset/plain-models-explain.md naming '@backstage/catalog-model' at patch, one adopter-facing sentence, no internal symbol names. (not minor; not Reusing one of the 38 pending changesets; not Running the changeset CLI) — Documentation-only on a published package at 1.10.2 is a patch; no pending changeset names this package; project instructions forbid the CLI and require editing .changeset files directly.
