### U05 — create `plugins/catalog-backend/src/processing/formerEntityRefs.ts` (codegen)

Behaviour: Parses and validates the annotation, decides whether a run needs a claim sync, and turns claim outcomes into errors.

Rules:
1. `parseFormerEntityRefs` applies the Annotation decision, then judges each piece in this order: it must match `/^([^:/]+):([^:/]+)\/([^:/]+)$/` with kind, namespace and name passing `makeValidator()`'s `isValidKind`, `isValidNamespace` and `isValidEntityName`; its kind must equal the entity's kind in lowercase; it must differ from `stringifyEntityRef(entity)`.
2. Validation runs on the lowercased piece; the error names the trimmed piece as it was written.
3. An invalid piece produces its error and is left out of `formerEntityRefs`. An entity with no annotation returns two empty lists.
4. `shouldSyncFormerEntityRefs` is true when the annotation key is present on the entity or `state?.[FORMER_ENTITY_REF_CLAIMS_STATE_KEY]` is truthy. It tolerates a state that is not a plain object.
5. `formerEntityRefClaimErrors` returns an `InputError` for each `rejected` and `lost` outcome, in order, and nothing for `active`.
6. All error text is exactly as the Claim error text decision gives it.

### U04 — create `plugins/catalog-backend/src/database/operations/formerEntityRefs/syncFormerEntityRefClaims.ts` (codegen)

Behaviour: Makes one claimant's claim rows match the refs it declares, and returns each declared ref's outcome.

Rules:
1. 1. Select the claimant's own rows by `claimant_entity_id` (`former_entity_ref`, `rejected_at`).
2. 2. Delete, in one statement scoped to `claimant_entity_id`, the own rows whose ref is not in `formerEntityRefs`; issue no delete when there are none.
3. 3. For declared refs with no own row, select `entity_ref` and `location_key` from `refresh_state` where `entity_ref` is one of them; issue no select when there are none.
4. 4. A new claim is rejected when a holder row exists and it is not the case that both location keys are non-empty and equal.
5. 5. Insert the new rows in one statement with `claimed_at: tx.fn.now()`, `rejected_at: tx.fn.now()` or `null`, and `.onConflict(['former_entity_ref', 'claimant_entity_id']).ignore()`. Existing rows are never updated, so a run with no change writes nothing (NFR-3).
6. 6. If `formerEntityRefs` is empty, return `[]`.
7. 7. Select `former_entity_ref` and `claimant_entity_id` where `former_entity_ref` is in `formerEntityRefs` and `rejected_at` is null, ordered by `claimed_at` asc then `claimant_entity_ref` asc; the first row per ref is its winner.
8. 8. Return one outcome per entry of `formerEntityRefs`, in that order: `rejected` when the own row is rejected, `lost` when the winner is another claimant, otherwise `active`.
9. 9. A holder never changes an outcome after rule 4: a recorded claim on a ref that a new entity takes stays `active` with no error.

Exports:
