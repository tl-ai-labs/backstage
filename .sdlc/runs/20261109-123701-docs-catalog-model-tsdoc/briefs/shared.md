## Conventions

- Comment-only change: add TSDoc comment lines and nothing else; never change, move, reformat or delete a code line, an import, an existing blank line, a release tag, or the copyright header, and add no blank line outside a comment block.
- Comment form: a `/**` line, ` * ` text lines, and a ` */` line, indented to the declaration it documents (2 spaces for interface members and class methods, column 0 for top-level functions), as the members of packages/catalog-model/src/entity/Entity.ts are documented.
- The first paragraph is one summary sentence ending in a period. When a unit gives remarks, write `@remarks`, then a blank ` *` line, then the remark paragraphs, then a blank ` *` line before the block tags. A blank ` *` line also separates the summary from `@remarks`.
- Block tags use `@param name - description` (a hyphen after the name, no trailing period on the description), as packages/catalog-model/src/validation/CommonValidatorFunctions.ts does; `@returns` text follows the same no-trailing-period form.
- Wrap comment text at 80 columns including indentation (Prettier does not wrap comments; existing comments in the package wrap near 80). Break only between words and never inside a backtick span or a `{@link ...}` tag.
- Any `{`, `}`, `<`, `>` or `@` in prose goes inside backticks, because TSDoc reads them as tags or HTML and API Extractor reports a warning in the API report. Use `{@link X}` only where a unit's rule writes it; every link target is a public export of @backstage/catalog-model.
- Write the sentences a unit's rules give, word for word and in that order; do not add, drop or reword a claim. U.S. English. Every statement has been checked against the implementation and its tests.
- packages/catalog-model/report.api.md and report-alpha.api.md are regenerated by `yarn build:api-reports` only; no unit edits them.

## Decisions

- Member comments on the eight kind interfaces: A multi-line `/** ... */` block directly above each of `apiVersion`, `kind` and `spec`, with no blank line added between members. (not single-line `/** text */` comments; not blank lines between documented members) — Entity.ts documents its members with multi-line blocks; adding blank lines would put non-comment lines in a diff that must be comment-only (NFR-2).
- Existing `/** @public */` blocks in conditions.ts: Replace each three-line block with the full comment, keeping its `/**`, ` * @public` and ` */` lines, with tag order summary, `@remarks`, `@public`, `@param`, `@returns`. (not a second comment block above the existing one; not moving `@public` below `@param`) — API Extractor reads only the comment block nearest the declaration; ref.ts already orders `@public` before `@param` and `@returns`.
- Return documentation: Type guards in conditions.ts get `@returns`; validator methods and policy `enforce` methods state their result in the summary and remarks and get `@param` only. (not `@returns` on all 21 methods and functions) — CommonValidatorFunctions documents its checks with `@param` only, and FR-2 alone asks for a stated return; fewer tags keep the comments short (NFR-1).
- Throwing in DefaultNamespaceEntityPolicy and GroupDefaultParentEntityPolicy: Their comments do not mention throwing at all. (not stating that they do not throw for a well-formed entity) — FR-4 allows either; leaving it out cannot be misread as an unqualified 'does not throw'.
- Schema named by SchemaValidEntityPolicy: The comment names the package's `Entity` JSON schema, the one the code compiles (src/schema/Entity.schema.json), not the separate entity envelope schema. (not calling it the entity envelope schema) — The package also exports an envelope validator built on EntityEnvelope.schema.json, which allows unknown root fields; the policy's schema does not, so the envelope name would mislead (NFR-1). The error message text still begins `Malformed envelope`.
- Changeset file: `.changeset/catalog-model-tsdoc.md`, one `patch` entry for `@backstage/catalog-model`. (not a random three-word changeset name) — The write contract allows only paths matching `.changeset/*catalog-model-tsdoc*.md`, and no file of that name exists.
