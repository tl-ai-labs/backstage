# Intent Brief — docs — TSDoc for the 45 undocumented catalog-model exports

## Context

Seed (from `/mmo:docs`): "Write accurate TSDoc for the 45 undocumented exports of @backstage/catalog-model."

The user's brief, verbatim:

> What to document: @backstage/catalog-model, which defines what a catalog entity is (kinds like Component, API, Group), how references such as component:default/foo are parsed and how entities are validated. 45 of its exports are marked (undocumented) in packages/catalog-model/report.api.md.
>
> Audience: plugin authors and other engineers who build against the entity model.
>
> Existing docs: update the package's source TSDoc in place, across kinds, relations, validation and entity helpers, then regenerate report.api.md. Match the TSDoc style the package already uses. Accuracy matters more than volume: describe what the code does, not what it sounds like it does.
>
> Acceptance criteria: yarn build:api-reports passes and packages/catalog-model/report.api.md contains zero (undocumented) markers.

Verified on branch `BS-DOC-04/opus55-plus-flash38-agsdk` at `f20fd9b59828`: `packages/catalog-model/report.api.md` carries exactly 45 `// (undocumented)` markers. (Discovery reported zero because it searched for `ae-undocumented`; the reports write the marker as `// (undocumented)`.) They are all members or functions, in four groups:

| Group | Count | Source file(s) |
|---|---|---|
| `apiVersion`, `kind`, `spec` of the eight kind interfaces `ApiEntityV1alpha1`, `ComponentEntityV1alpha1`, `DomainEntityV1alpha1`, `GroupEntityV1alpha1`, `LocationEntityV1alpha1`, `ResourceEntityV1alpha1`, `SystemEntityV1alpha1`, `UserEntityV1alpha1` | 24 | `src/kinds/<Kind>EntityV1alpha1.ts` |
| `isApiEntity`, `isComponentEntity`, `isDomainEntity`, `isGroupEntity`, `isLocationEntity`, `isResourceEntity`, `isSystemEntity`, `isUserEntity` | 8 | `src/entity/conditions.ts` |
| The static methods `isValidAnnotationKey`, `isValidAnnotationValue`, `isValidApiVersion`, `isValidKind`, `isValidLabelKey`, `isValidLabelValue`, `isValidNamespace`, `isValidObjectName` of `KubernetesValidatorFunctions` | 8 | `src/validation/KubernetesValidatorFunctions.ts` |
| `enforce` of `DefaultNamespaceEntityPolicy`, `FieldFormatEntityPolicy`, `GroupDefaultParentEntityPolicy`, `NoForeignRootFieldsEntityPolicy`, `SchemaValidEntityPolicy` | 5 | `src/entity/policies/<Policy>.ts` |

None of the 45 is in `src/kinds/relations.ts` or the reference-parsing code (`src/entity/ref.ts`); those areas are already documented.

`packages/catalog-model/report-alpha.api.md` carries 25 further markers, which the brief does not target. Three of them belong to a copy of `ApiEntityV1alpha1` that the alpha report includes, so documenting that interface also removes them, and the alpha report must be regenerated alongside the main one.

On the untouched branch, `yarn build:api-reports` exits 0 and leaves the tree clean, so any report change after the run is the run's own. The test command below exits 1 there only because of the 45 markers.

## Goal

Every one of the 45 undocumented members and functions in `packages/catalog-model/report.api.md` gets a TSDoc comment in its source file that states accurately what the code does, in the TSDoc style the package already uses (STYLE.md: `/** */` blocks, a one-line summary, `@remarks` for detail, `@param name - description`, `{@link}`; release tags kept as they are). The API reports are then regenerated so they show the new documentation, and no `(undocumented)` markers remain in `report.api.md`.
