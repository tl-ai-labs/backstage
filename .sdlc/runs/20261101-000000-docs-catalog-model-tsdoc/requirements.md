# Requirements: TSDoc for the 45 undocumented exports of @backstage/catalog-model

Job: `docs`. Audience: API consumers (adopters and plugin authors). Source: `intent_brief.md`, approved at Gate 0.
Counts confirmed against `packages/catalog-model/report.api.md` at `f20fd9b59828`: 45 `(undocumented)` markers.

## In scope

1. Add TSDoc to the 8 `is*Entity` functions in `packages/catalog-model/src/entity/conditions.ts`.
2. Add TSDoc to the 24 `apiVersion`, `kind` and `spec` members of the 8 kind interfaces in
   `packages/catalog-model/src/kinds/*EntityV1alpha1.ts`.
3. Add TSDoc to the 8 `isValid*` static methods in
   `packages/catalog-model/src/validation/KubernetesValidatorFunctions.ts`.
4. Add TSDoc to the 5 `enforce` methods in `packages/catalog-model/src/entity/policies/`.
5. Regenerate `packages/catalog-model/report.api.md` and `report-alpha.api.md`, scoped to `packages/catalog-model`.
6. Add one `patch` changeset for `@backstage/catalog-model`.

## Out of scope

1. The 22 entries that appear only in `report-alpha.api.md`. Its marker count falls from 25 to 22 only because
   `src/alpha.ts` re-exports `ApiEntityV1alpha1`.
2. Rewriting existing TSDoc, even where it could be better.
3. Changes to `/docs`, the README, or any other package, including other packages' API reports.
4. Any behaviour, type or test change.
5. `.gitignore`, which stays unchanged.

## Functional requirements

### Entity guards

- **FR-1** Each of `isApiEntity`, `isComponentEntity`, `isDomainEntity`, `isGroupEntity`, `isLocationEntity`,
  `isResourceEntity`, `isSystemEntity` and `isUserEntity` has a description, placed in its existing
  `/** @public */` block (extended, not duplicated), that states the check the function actually performs,
  including how `kind` is compared. Each function ends up with exactly one TSDoc block.

### Kind interfaces

- **FR-2** Each of the 8 interfaces `ApiEntityV1alpha1`, `ComponentEntityV1alpha1`, `DomainEntityV1alpha1`,
  `GroupEntityV1alpha1`, `LocationEntityV1alpha1`, `ResourceEntityV1alpha1`, `SystemEntityV1alpha1` and
  `UserEntityV1alpha1` has TSDoc on its `apiVersion`, `kind` and `spec` members (24 members). The comment states the
  values the type allows and agrees with the kind's JSON schema in `src/schema/kinds/`. A `spec` comment describes
  the object for that kind; existing comments on nested `spec` fields are not touched.

### Validators

- **FR-3** Each of `KubernetesValidatorFunctions.isValidApiVersion`, `isValidKind`, `isValidObjectName`,
  `isValidNamespace`, `isValidLabelKey`, `isValidLabelValue`, `isValidAnnotationKey` and `isValidAnnotationValue` has
  TSDoc that states the actual rules the method applies: the value type it accepts, its length limits, its allowed
  characters and its prefix handling, read from `src/validation/CommonValidatorFunctions.ts` and confirmed against
  the validator tests. The comment states what the code does, not what Kubernetes documents, where the two differ.

### Policies

- **FR-4** The `enforce` method of each of `DefaultNamespaceEntityPolicy`, `FieldFormatEntityPolicy`,
  `GroupDefaultParentEntityPolicy`, `NoForeignRootFieldsEntityPolicy` and `SchemaValidEntityPolicy` has TSDoc that
  states what that policy checks or changes on the entity, what it resolves to, and when it rejects.

### API reports

- **FR-5** `report.api.md` and `report-alpha.api.md` of `packages/catalog-model` are regenerated by the repository's
  API report command, scoped to that package, never hand-edited. The orchestrator runs this deterministic step
  itself under provenance after the typed files are in. It is not a typed unit and not a `tooling` unit (a `docs`
  job holds none), so the change spec does not plan it.

### Changeset

- **FR-6** One new file under `.changeset/` gives `@backstage/catalog-model` a `patch` bump. Its message is written
  for adopters in plain language and names no internal symbols. If an unreleased changeset already covers this
  documentation change, that is reported instead of adding a second one.

## Non-functional requirements

- **NFR-1** Comments only. No executable or type change in any source file. The compiled output of every source
  file with comments removed is identical before and after the run.
- **NFR-2** Accuracy. Every statement is verified against the implementation, the JSON schema or the tests. Nothing
  is inferred from a name alone.
- **NFR-3** Style. Wording follows `docs/contribute/doc-style-guide.md` (present tense, active voice, plain language)
  and the surrounding TSDoc in each file, matching how neighbouring comments are written.
- **NFR-4** TSDoc validity. No comment adds an API Extractor or TSDoc warning line to either report. Characters TSDoc
  treats as markup (`@`, `{`, `}`, `<`, `>`) appear only inside backticks or escaped.
- **NFR-5** Source files keep their existing copyright year.
