## Conventions

- Formatter is Prettier with @backstage/cli/config/prettier: 80 columns, 2-space indent, single quotes, trailing commas everywhere, arrow parens avoided; the plan runs `yarn prettier --write` on each changed file only.
- Match the style of the file being edited; change only the lines a site names and keep every other line byte-for-byte, including the existing Apache 2.0 header year.
- This change creates no new .ts/.tsx/.js source file; if one were needed it would start with the Apache 2.0 header `Copyright 2026 The Backstage Authors`.
- React APIs are taken as named imports (`import { useMemo, useSyncExternalStore } from 'react';`, `import { createRoot } from 'react-dom/client';`), never through a `React.` namespace or a default `ReactDOM` import.
- package.json files: 2-space JSON, key order unchanged, no trailing comma after the last entry of an object; the React peer range is exactly `^18.0.0`; `peerDependenciesMeta` is never touched.
- Tests use Jest `describe`/`it` with @testing-library/react; prefer fewer thorough tests, `screen`/`findBy*` over `waitFor`, and no test IDs.
- Changesets are hand-written `.changeset/<slug>.md` files: YAML front matter of `'<package name>': <bump>` lines in single quotes, a blank line, then one adopter-facing paragraph; a breaking change starts with `**BREAKING**:`; never name an internal (non-public) code symbol.
- Docs follow docs/contribute/doc-style-guide.md: present tense, active voice, address the reader as you, no statements about the future, code style for package names, file names and version ranges.
- Never run `yarn build`, `yarn changesets version`, `yarn release`, any changeset CLI, or bare `git stash`; never edit ESLint, Prettier or TypeScript config files.

## Decisions

- React peer range: Every workspace package with React peers declares `"@types/react": "^18.0.0"`, `"react": "^18.0.0"`, `"react-dom": "^18.0.0"`; repo-tools peer-deps holds one `peerDependencies` const with those values and no per-package exception set. (not ^18.0.2 peers (the local devDependency version); not keeping a React 18 only allowlist) — Matches the existing React 18 only shape of @backstage/ui, so the check collapses to one expected map.
- Legacy render fallback removal: dev-utils, frontend-dev-utils and techdocs import `createRoot` statically from 'react-dom/client' and call `createRoot(element).render(node)` directly; the dynamic-import promise, the `HAS_REACT_DOM_CLIENT` branch and the side-effect `import 'react-dom';` lines are removed. (not keep a dynamic import('react-dom/client') promise; not keep HAS_REACT_DOM_CLIENT defined as true for third-party readers) — Gate 1 requires the flag gone (FR-11, AC-4); a React 18 root already schedules rendering, and createDevApp tests that mock react-dom/client keep working with a static import inside jest.isolateModules.
- legacyRoot option: Remove `LegacyRootOption` and the `legacyRoot` option outright from @backstage/test-utils, with a major changeset. (not mark it @deprecated and keep it) — Gate 0 chose the breaking removal (FR-14, AC-5, AC-8).
- CLI React version warning: Keep the single check in `checkReactVersion()` of packages/cli-module-build/src/lib/bundler/server.ts (called once from serveBundle); it warns when the resolved react major is below 18 and links https://backstage.io/docs/tutorials/react18-migration; the startFrontend.ts warning is deleted. (not fail the start command; not a new helper module) — Gate 1 kept a warning; server.ts already resolves react/package.json, and keeping its lines 269-275 unchanged keeps the knip report location `server.ts:274:43` valid.
- react-aria useId: Popover, Tooltip, Table and TablePagination take `useId` from 'react'; none passes the id into a react-aria API that needs react-aria's own id (they feed SVG `id`/`use href`, `aria-describedby` and a live region `id`), so all four switch. — FR-7; React 18's useId gives the same per-instance uniqueness.
- Lockfile: One `yarn install` from the repo root after every manifest edit (the lockfile records workspace peerDependencies as well as the removed use-sync-external-store deps). (not install right after the three shim manifests only) — A single install after all manifest edits leaves yarn.lock consistent for `yarn install --immutable`.
- Generated reports: packages/test-utils/report.api.md is regenerated by `yarn build:api-reports packages/test-utils`; knip reports are edited by hand only where a removed finding exists (plugins/app use-sync-external-store, cli-module-build hasReactDomClient.ts); the frontend-plugin-api and ui knip reports never list the removed deps and are left alone. (not running build:knip-reports (writes a temporary root knip.json outside the allowlist and rewrites already-drifted line numbers)) — Gate 0 wants API reports from tooling; the knip deltas are fully determined and small.
- Changesets: Seven new files: react18-required-peer-ranges.md (54 published peer-range packages), react18-test-utils-legacy-root.md, react18-cli-module-build.md, react18-cli-module-test-jest.md, react18-cli-module-new-templates.md, react18-repo-tools-peer-deps.md, react18-ui-builtin-hooks.md; breaking changes are major for version >= 1.0.0 and minor below; the non-breaking @backstage/ui changeset is patch (ui is below 1.0.0); private packages and @backstage/eslint-plugin (doc example only) get none. — Gate 0 release policy; packages needing different text get separate files.
